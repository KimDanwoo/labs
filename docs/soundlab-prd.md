# PRD — soundlab

> SoundCloud에 올린 내 곡 24개를 듣는 앱. 곡을 고르면 아트워크가 화면 전면에서 픽셀로 흩어진 채 나타나
> 액자로 수축하며, 어두운 곳부터 자리를 잡고 조명이 마지막에 켜진다.
>
> 최종 수정 2026-08-19 · 상태: 디자인 확정, 구현 착수
> 디자인 목업: https://claude.ai/code/artifact/ee3fdbae-5cfb-4075-8919-787e071ff78f

## 1. 목적과 성공 기준

`soundcloud.com/danwooking`의 24곡을 SoundCloud 플레이어 UI가 아닌 자체 화면에서 듣는다.
재생은 SoundCloud를 통하고(재생수 집계 유지), 화면은 왼쪽 플레이리스트 + 오른쪽 픽셀 파티클 스테이지로 구성한다.

- 24곡 전곡이 앱 안에서 재생·시크된다.
- 집결 상태에서 아트워크가 원본 그림으로 읽힌다. 스페클(픽셀 튐)이 없다.
- 곡 전환이 단일 제스처로 읽힌다. 여러 방식이 번갈아 나오지 않는다.
- 재생 중 파티클과 진행 헤드가 곡의 실제 진폭에 반응하되, 그림이 흔들리지 않는다.
- 모바일에서 진행바·컨트롤이 화면 맨 아래에 온다.
- 새 곡을 올리고 배포하면 목록에 반영된다.
- 런타임 서버 의존이 없다(정적 페이지).

| 런타임                                                         | Next 16.2.6 · React 19.2.4 (catalog)                                                                               |

### 확실한 제약

**iframe 오디오는 cross-origin이므로 Web Audio `AnalyserNode`를 붙일 수 없다.** 주파수 분해(FFT)는 불가능하다.
→ `waveform_url`의 진폭 샘플로 대체한다(§5). "베이스에만 반응하는 저역 펌핑" 류는 이 설계로 구현할 수 없다.

### 함정 — 아트워크 URL의 확장자

`artwork_url`은 `…-large.jpg` 또는 `…-large.png`로 온다. 접미사만 바꾸고 **확장자를 고정하면 절반 이상이 404**가 난다.

비율은 고정이 아니다. 2026-08-19 작업 중 관측: 오전에 `.png` 17 / `.jpg` 7이었는데 몇 시간 뒤 15 / 9로 바뀌었다
(`너랑만 잠들래`, `너의 이름을 부를 때`가 `.png` → `.jpg`). SoundCloud가 아트워크를 재인코딩한다.
**곡 수나 확장자 비율을 코드나 테스트에 하드코딩하지 않는다.**

```ts
const [, base, ext] = artworkUrl.match(/^(.*)-[a-z0-9]+(\.[a-z]+)$/)!;
const url = `${base}-t500x500${ext}`;
```

### 모르는 것

- SoundCloud 공식 API의 신규 앱(client_id) 발급 가능 여부. 개발자 포털에서 직접 확인해야 한다.
- `api-v2` + 익명 `client_id` 경로의 수명. 비공식이라 예고 없이 깨질 수 있다(§9).

## 3. SSR을 쓰지 않는다

서버가 필요한 유일한 이유는 렌더링이 아니라 **비공식 `api-v2` 호출을 브라우저에서 할 수 없다는 것**이다.
그런데 요구사항은 "새 곡을 올리고 **배포하면** 반영"이고, 그것은 빌드 타임 스크립트로 완전히 충족된다.

런타임 fetch(+`revalidate`)를 넣으면 얻는 것은 "배포 없이도 주기적 갱신" 하나인데,
대가로 서버 런타임·캐시 무효화·라이브/폴백 분기가 붙는다. 지금 필요하지 않다.

**결론**: 페이지는 정적. `tracks.ts`가 런타임의 유일한 목록 소스이고, 빌드 전에 스크립트가 그것을 갱신한다.
"배포하지 않고 갱신"이 필요해지면 그때 라우트 핸들러 하나를 추가한다.

WebGL 캔버스와 재생 상태는 당연히 클라이언트 컴포넌트다. 서버에서 렌더할 수 있는 것이 없다.
다만 **첫 페인트에 빈 무대를 보여주지 않기 위해**, 첫 곡 아트워크를 `<img>`로 정적 렌더해 `.slot`에 깔고
캔버스가 준비되면 감춘다(LCP 확보).

## 4. 화면

```
┌──────────────────┬────────────────────────────────────────┐
│ SOUNDLAB         │                                        │
│ DANWOO · 24      │           ┌──────────────┐             │
│ TRACKS · 1시간22분│           │  아트워크     │             │
├──────────────────┤           │   (.slot)    │             │
│ 01 ▮▮▮ 꿈은…3:15 │           └──────────────┘             │
│ 02  ·  노을 3:20 │            01 / 24 · R&B & SOUL        │
│ …  (24행 스크롤) │              꿈은 아니야                │
├──────────────────┴────────────────────────────────────────┤
│ ━━━━━━━━━━━━━━●─────────────────────────────────────────  │
│ 1:22      ⤨  ⏮  ▶  ⏭  🔁¹                    3:15  SC   │
└───────────────────────────────────────────────────────────┘
```

**왼쪽 패널** — 헤더(워드마크 + `DANWOO · 24 TRACKS · 1시간 22분`) + 24행 목록.
행은 `번호 / 장르점 · 제목 / 길이`. 현재 곡 행은 브라스 왼쪽 마커 + 장르점 대신 **파형 진폭으로 움직이는 3바 미터**.
곡이 바뀌면 목록이 그 행으로 자동 스크롤한다.

**오른쪽 스테이지** — 파티클이 모일 자리를 `.slot`(정사각 예약 칸)으로 두고 **GL이 그 요소의 rect를 읽어**
`uSide`/`uCenter`를 계산한다. 좌표를 눈대중으로 오프셋하지 않는다. 아래에 `번호 / 전체 · 장르`와 곡 제목.

**하단 transport (전체 폭)** — 진행바(드래그 시크) + 컨트롤 행.
좌측 경과시간 / 중앙 `셔플 · 이전 · 재생 · 다음 · 한곡반복`(인라인 SVG, 재생만 흰 원형) / 우측 총시간 + SoundCloud.
토글은 `aria-pressed`로 상태를 갖고 켜지면 브라스로 물든다.

**모바일(≤820px)** — 1열로 접고 `아트워크 → 목록 → transport` 순.
세 영역에 **명시적 `order`를 부여한다.** 생략하면 기본값 `0`이 되어 그리드 자동 배치에서 맨 위로 올라간다(§9).

**첫 진입** — 플레이스홀더 카피를 두지 않는다. 처음부터 1번 곡 메타를 표시하고 재생만 정지 상태로 시작한다.

## 6. 파티클 스테이지

**raw WebGL2, 라이브러리 0개.** `three` / R3F를 쓰지 않는다(§7).

### 렌더 파이프라인

```
파티클 → 누적 FBO(장노출 트레일) → 브라이트패스 → 블러 2패스(가로·세로) → 합성
```

- 누적 버퍼는 **빛만** 담는다(검정으로 clear). 배경색은 합성 단계에서 더한다.
  그래야 트레일이 배경색과 정확히 맞물린다.
- 트레일은 **움직일 때만** 남긴다. `morph` 속도로 감쇠율을 계산해 집결이 끝나면 0으로 보낸다(정지 상태는 선명).
  `speed = |morph - prevMorph| / k`, `trailAct += (min(1, speed*140) - trailAct) * 0.14k`, `decay = trailAct * 0.86`.
- 브라이트패스 임계 `0.7`, 블룸 합성량 `0.62`, 블룸 타깃은 절반 해상도.

### 파라미터

| 항목        | 값                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------- |
| 격자        | `clamp(round(side * dpr / 1.9), 120, 288)` — 표시 크기에 맞춰 자동. 1600px 화면에서 259² ≈ 67,000 |
| 텍스처      | 아트워크 `t500x500`, `CLAMP_TO_EDGE` + `LINEAR`, 밉맵 없음                                        |
| 블렌딩      | `SRC_ALPHA, ONE_MINUS_SRC_ALPHA`, depth test 없음                                                 |
| 포인트 크기 | `max(1.5, side/grid * dpr * 1.72) * (1 + (1-m)*1.5) * persp`                                      |
| 알파        | `0.05 + m * 0.95`                                                                                 |
| morph 이징  | 집결 `0.038`, 산개 `0.075` (프레임 보정 `dt/16.7`)                                                |
| 깊이        | `uDepth = side * 0.12`, `uFocal = 1600`                                                           |
| 진폭 스무딩 | `level += (raw - level) * 0.12`                                                                   |

### 단일 전환 제스처

```glsl
// 도착 순서를 휘도로 — 어두운 곳이 먼저 자리잡고 조명이 마지막에 켜진다
float delay = lum * 0.44;
float m = clamp((uMorph - delay) / max(0.2, 1.0 - delay), 0.0, 1.0);

// 시작 자리: 화면 전체에 흩어지되 확대된 이미지의 구조가 희미하게 남는다
float fill = max(uRes.x, uRes.y) / max(1.0, uSide) * 1.35;
vec2 spread = (vec2(hash(a_uv * 13.3), hash(a_uv * 91.7)) - 0.5) * uRes * 1.12;
vec2 away = mix(spread, rel * fill, 0.35);

vec2 rp = mix(away, rel, m) * (1.0 + uLevel * 0.009 * m);
vec2 origin = mix(vec2(0.0), uCenter, m);
```

곡 전환은 **완전히 흩어진 뒤 텍스처를 교체하고 다시 모은다**. 교체는 가장 크고 가장 옅은 순간에 일어나 보이지 않는다.
`delay` 계수 `0.44`가 연출의 조절 손잡이다 — 키우면 어둠이 오래 머물고 조명이 극적으로 터진다.

### 깊이와 호흡 — 스페클을 만들지 않는 규칙

- 깊이는 **저주파 휘도**로 계산한다(5탭 평균, uv 오프셋 `0.006`).
  픽셀 단위 휘도를 쓰면 인접 픽셀의 원근 배율이 달라져 서로 벌어지고 **스페클이 된다.**
- 재생 중 호흡은 좌표를 섞지 않는 **균일 확대**(`rp *= 1 + level*0.009*m`)로 한다.
  파티클마다 다른 방향으로 미는 노이즈는 반짝임으로 읽힌다.

### 음악 악센트 — 신호 설계

**전제: 파형은 포화 상태다.** 24곡을 계산한 결과 정규화 전 진폭은 평균 0.76–0.82, 표준편차 0.09–0.14다.
마스터링된 트랙이라 값이 거의 상한에 붙어 있고, **정규화하지 않으면 어떤 연출을 붙여도 티가 나지 않는다.**
해상도도 확인해 둔다 — 1800 샘플 / 곡 길이 = **약 105–111ms per sample (≈9Hz)**.
120BPM의 비트 간격 500ms는 약 4.6 샘플이므로 **비트 트래킹은 불가능하다.** 프레이즈 수준만 신뢰할 수 있다.

세 신호를 파생한다.

| 신호          | 계산                                                                        | 쓰임                                                                        |
| ------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `level`       | 곡별 **백분위 재매핑**(p10→0, p95→1) 후 위치의 진폭, 스무딩 `0.12`          | 파티클 균일 확대 2%, 진행 헤드 글로우, 레벨미터                             |
| `swell`       | 정규화 파형의 **4초 이동평균**, 스무딩 `0.04`                               | 블룸량 `0.5 + swell*0.35`, 휘도 깊이 `side*(0.12+swell*0.06)`, 장르 색 번짐 |
| `pre` / `hit` | 곡별 **피크 3개**를 미리 뽑아, 300ms 전 들이쉼(`pre`) → 900ms 릴리스(`hit`) | `pre`는 1.2% 수축, `hit`는 블룸 문턱 `-0.12`·블룸량 `+0.5`·포인트 확대 34%  |

정규화 효과는 측정으로 확인했다 — 평균 0.8±0.1이던 신호가 **평균 0.5, 편차 0.30**의 실제 0–1 범위가 된다.

**악센트는 문턱이 아니라 개수로 고른다.** 같은 고정 문턱으로 국소 최대를 세면 곡마다 5개에서 94개까지 갈린다
(꿈은 아니야 5 / 노을 18 / 장마 16 / 바람이 부는 쪽으로 94). 문턱 방식은 어떤 곡은 아무 일도 없고
어떤 곡은 계속 번쩍인다. **상위 3개, 최소 간격 8초**로 고정한다.

`pre`가 존재하는 이유는 이 앱이 **곡의 미래를 알고 있다**는 것이다. 파형 전체를 미리 받으므로 피크가 오기 전에
미리 들이쉴 수 있다. 실시간 주파수 분석으로는 원리적으로 불가능하고, 반응이 아니라 안배로 읽힌다.

### 하지 않기로 한 것

- **피크마다 번쩍이기** — 9Hz에서는 비트가 아니라 스터터로 보이고 안정감과 충돌한다.
- **파형 그래프 노출** — §9. 화면에 파형 UI를 두지 않는다는 결정은 유지한다.

## 7. `three`를 쓰지 않는 이유

catalog에 `three` / `@react-three/fiber` / `@react-three/postprocessing`이 있고 `prairie`가 쓰고 있어 도입 비용은 낮다.
그럼에도 쓰지 않는다 — 이 화면에서 three가 주는 실질적 이득은 포스트프로세싱 하나였고,
그것을 brightpass + 블러 2패스로 직접 구현해 이미 검증했다. 씬 그래프·카메라·인스턴싱은 쓸 데가 없다.
검증까지 끝난 셰이더를 R3F로 이식하는 리스크와 번들 증가를 정당화하지 못한다.

```ts
  permalinkUrl: string;

```

`entities/track/model/constants/tracks.ts`에 24곡을 리터럴로 커밋한다. 런타임 조회 없음.
아트워크는 `t500x500`을 런타임에 URL로 로드한다(인라인하지 않는다). 파형은 곡 단위 메모리 캐시(곡당 약 8KB).

### 동기화 — `scripts/sync-tracks.mjs`

1. `soundcloud.com/danwooking/tracks` HTML → 참조된 JS 번들에서 익명 `client_id` 추출
2. `api-v2.soundcloud.com/users/51779680/tracks?limit=50` 호출
3. 필요한 필드만 골라 `tracks.ts` 생성 (`artwork_url`을 base + ext로 분해)

**빌드 전에 실행하되 실패해도 빌드를 깨지 않는다.** 실패 시 경고만 남기고 커밋된 `tracks.ts`를 그대로 쓴다.
스크립트가 비공식 경로에 의존하므로, 그것이 깨지는 날 배포까지 막혀서는 안 된다.

빌드 로그에 곡 수를 출력한다. 조용히 옛 목록으로 배포되면 눈치채지 못한다.

### 주기적 갱신 — cron

폴백이 오래되지 않게 같은 스크립트를 cron으로 돌린다. 이 리포에 같은 패턴이 3개 있으므로
[`.github/workflows/dansoon-weekly-bestseller.yml`](../.github/workflows/dansoon-weekly-bestseller.yml)을 그대로 따른다.

- `schedule` cron(주 1회) + `workflow_dispatch`(수동)
- `git diff --cached --quiet`면 **조용히 종료**(변경 없는 주에 빈 커밋을 만들지 않는다)
- 변경이 있으면 `feature/<date>-soundlab-tracks` 브랜치 → PR → squash merge → 그 푸시로 자동 배포

## 9. 시도했다가 버린 것

다시 제안하지 않기 위해 기록한다. 전부 실제로 만들어 화면을 보고서야 알게 된 것들이다.

| 시도                                        | 버린 이유                                                                                                                                                                |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 아트워크 회전 궤도(나선 캐러셀)             | 올드하게 읽힌다                                                                                                                                                          |
| 정적 편집물 레이아웃(증명사진 + 인덱스)     | 고급스럽지만 화면이 죽어 있고 레이아웃이 지루하다                                                                                                                        |
| 커서 궤적으로 파티클 밀어내기               | 안정감을 해친다. 초기 방사형 구현은 검은 별 모양 구멍을 만들었다                                                                                                         |
| 컬 노이즈 산개                              | **트레일과 원리적으로 충돌한다.** 트레일은 이동 궤적을 남기고 컬은 공간 고정 벡터장이므로 파티클이 유선을 그려 격자·만다라 무늬가 된다. 파라미터를 1/8로 줄여도 마찬가지 |
| 전환 모드 5종(방사·소용돌이·전단·터널·낙하) | 번잡하다. 전환은 한 가지여야 그 자체가 작품의 서명이 된다                                                                                                                |
| 바람 모드(단일 방향 이탈)                   | 최대 `2.05 × side` 밀어내 이미지가 화면 밖으로 사라졌다. 전환 중간에 볼 게 없으면 전환이 아니다                                                                          |
| 순수 줌(채우다 작아지기만)                  | 사건이 없어 심심하다. 크기만 변한다                                                                                                                                      |
| 픽셀 단위 휘도 깊이                         | 인접 픽셀의 원근 배율이 달라 스페클이 된다(§6)                                                                                                                           |
| 파티클별 랜덤 시차 조립                     | 번잡함의 일부. 휘도 순서라는 의미 있는 규칙으로 대체                                                                                                                     |
| mp3 자체 호스팅                             | `waveform_url`이 CORS 허용으로 진폭을 준다. FFT가 꼭 필요해지면 그때 재검토                                                                                              |
| PNG → JPEG 재인코딩                         | 측정 결과 원본 PNG가 JPEG q86보다 작았다(139KB → 175KB)                                                                                                                  |
| 런타임 fetch + revalidate                   | SSR이 과하다(§3)                                                                                                                                                         |
| 첫 진입 플레이스홀더 카피                   | 화면과 모순이었다(1번 곡 커버가 모여드는데 문구는 "24곡")                                                                                                                |

## 10. 조작

| 입력                  | 동작                          |
| --------------------- | ----------------------------- |
| 목록 행 클릭          | 그 곡 재생 (같은 곡이면 토글) |
| `Space` / `K`         | 재생·정지                     |
| `→` / `←`             | **10초** 앞/뒤                |
| `L` / `J`             | 10초 앞/뒤                    |
| `0`–`9`               | 해당 퍼센트 지점              |
| `Home` / `End`        | 처음 / 끝                     |
| `Shift+N` / `Shift+P` | 다음 / 이전 곡                |
| 진행바 드래그         | 시크                          |

YouTube 체계를 기준으로 했으나 **방향키만 10초**다(YouTube 원본은 5초, 10초는 `J`/`L`). `SEEK_SEC` 한 곳으로 관리한다.

버튼에 포커스가 있을 때 `Space`는 브라우저가 클릭으로 처리하므로 전역 핸들러에서 걸러 **이중 발동을 막는다.**
`metaKey`/`ctrlKey`/`altKey` 조합은 가로채지 않는다.

곡이 끝나면 `한곡 반복`이면 제자리 재시작, `임의재생`이면 무작위, 아니면 다음 곡.

## 13. 검증 방법

WebGL은 눈으로 보지 않으면 만들 수 없다. 목업 단계에서 headless Chrome으로 확인했고 앱에서도 같은 방법을 쓴다.

```bash
# 상태를 얼려 찍는 정적 검증(목업)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --enable-unsafe-swiftshader --hide-scrollbars \
  --window-size=1600,1000 --virtual-time-budget=10000 \
  --screenshot=out.png "file://$PWD/page.html"
```

**`--virtual-time-budget`은 rAF 루프가 계속 도는 페이지에서 데드락한다.** 가상시간이 소진되지 않아
스크린샷이 영구 대기한다(실제로 5분 타임아웃을 맞았다). 실제 앱처럼 루프가 멈추지 않는 페이지는
CDP로 붙어 실제 시간만큼 기다린 뒤 캡처해야 한다. 도구는 `scratchpad/shot.mjs` 참고:
Chrome을 `--remote-debugging-port`로 띄우고 `/json/list`에서 타깃을 찾아 WebSocket으로
`Page.navigate` → 대기 → `Page.captureScreenshot`. Node 24의 내장 WebSocket으로 의존성 없이 된다.

- **상태를 얼려서 찍는다**(집결/중간/산개, 조용/고조/피크). rAF 애니메이션은 캡처 시점이 불확정이라
  얼리지 않으면 검증이 안 된다. 얼릴 때는 `select()`를 먼저 호출하고 그 다음에 상태를 덮어써야 한다.
  순서를 바꾸면 `select()`가 전환을 다시 시작시킨다.
- **최상위 `let`은 `window` 속성이 아니다.** `Object.defineProperty(window, 'position', …)`로는 고정되지 않는다.
  주입 코드가 같은 스크립트 스코프에 있으면 `setInterval(() => { position = X; hit = 1; }, 4)`로 직접 고정하는 것이
  유일하게 확실한 방법이다. 타이밍으로 순간을 맞히려 하면 헤드리스의 프레임 지연 때문에 어긋난다
  (SwiftShader에서 프레임이 64ms를 넘으면 dt 상한 때문에 재생 시계가 실제보다 느리게 간다).
- 레이아웃 수치가 의심되면 스크린샷으로 눈대중하지 말고 `--dump-dom` + `document.title`에
  `getBoundingClientRect()` 결과를 실어 **실측한다.** 헤드리스는 뷰포트 폭을 클램프하므로
  (`--window-size=414` → `innerWidth: 500`) 스크린샷만 보면 정상 레이아웃을 잘림으로 오진한다.
- 셰이더 컴파일 실패는 화면만 검게 만든다. `window.onerror`를 수집해 `document.title`로 확인한다.
- 단축키는 `KeyboardEvent`를 실제로 dispatch하고 `position`을 읽어 검증한다.

## 14. 마일스톤
