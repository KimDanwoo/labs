# 월드 엔진 출처와 변경 기록

월드 엔진은 Bruno Simon의 `folio-2025` 커밋 `70764a94756cc4de564e493c8ba46c4b5fe03ed1`을 포크했다.
원본 출처: https://github.com/brunosimon/folio-2025 · 라이선스: MIT, Copyright (c) 2025 Bruno Simon. 전문은 [LICENSE](./LICENSE).

- 엔진 소스: `src/views/drive/lib/engine/`. 아래 001–006 패치를 모두 적용한 상태에서 앱으로 옮겼다. 패치 파일·`origin:*` 스크립트는 더 이상 쓰지 않는다.
- 모델·텍스처·사운드(`static/`)는 커밋하지 않는다. `pnpm --filter danwoo-island world:sync`가 같은 커밋의 `static/`만 sparse checkout으로 받아 `public/world/`에 둔다. `dev`·`build`가 자동으로 먼저 실행한다.
- 아래 기록의 "패치 적용", "`origin:verify`", "`public/origin`"은 포크 이전 방식의 검증 기록이다.

## 포크 이식 (2026-11-13)

- 진입: `app/page.tsx` → `views/drive`. 원본 `index.html` 본문을 React 컴포넌트로 옮겼고(`ui/`), 엔진은 `WorldBoot`의 effect에서 한 번만 시작한다. 엔진은 문서 수명과 같고, DOM이 다시 만들어지면 새로고침한다.
- Vite 전용 처리 교체: `import.meta.env` → `worldConfig.js` 상수, `@dimforge/rapier3d`(wasm) → 같은 버전의 `@dimforge/rapier3d-compat` + `init()`, Stylus → Vite 결과 CSS(`ui/world.css`, URL만 `/world/`로 교체).
- 에셋 경로: three 로더는 `DefaultLoadingManager.setURLModifier`, Howler·지도 이미지·JSX는 `config/worldAsset.ts`로 `/world/`를 붙인다.
- 실행 경로의 `innerHTML` 3곳(음악 알림·지도 위치·WebGPU 툴팁)은 DOM API로 바꿨다. 엔트리에서 닿지 않는 원본 모듈(업적·서버·방명록 등 15개)은 삭제했다.

## 이전 패치 기록

앱 이름이 Morning Drive였던 시기의 기록이다. 명령의 `morning-drive`, 증거 경로 `output/verification/morning-*`는 당시 이름 그대로 둔다.

### 001-entry.patch

첫 변경 범위는 진입 화면의 이름·출발 안내·메뉴 소개다. 추적 스크립트는 제거하고 원작자 표시는 유지한다.
HTML의 정적 리소스 경로는 `/origin/`에서도 작동하도록 상대 경로로 바꾼다.
이 첫 패치에서는 월드 안의 원본 글자·포트폴리오 오브젝트를 유지했다. 출발 구역 이름은 이후 003에서 교체한다. 이는 완성된 개인 포트폴리오가 아니라 원본 품질을 보존하는 첫 작업본이다.

원본 월드의 외형을 바꾸려면 별도 패치를 추가하고, 고정된 카메라·시간·계절에서 전후 캡처를 남긴다.
이 단계의 허용 목록을 늘리는 것만으로 시각 검증을 대신하지 않는다.

### 002-loading-performance.patch

원본 동작과 미술을 보존하면서 초기화 상태·실패 복구와 렌더 해상도만 조정한다.

- `Game.js`: 초기화 실패를 처리하고 에셋/그래픽 준비를 구분한다.
- `World/Intro.js`: 원본 출발 입력을 등록한 뒤 준비 완료를 표시한다. 원본의 라벨 등장 애니메이션은 그대로 유지한다.
- `Viewport.js`: 터치/작은 화면은 DPR 최대 1.5와 150만 픽셀, 데스크톱은 DPR 최대 2와 400만 픽셀로 제한한다.
- `PreRenderer.js`: 준비용 큐브 렌더 타깃을 사용 후 해제한다.
- `morning-startup.js/css`: 진행 안내, 12초 지연 및 실패 시 재시도. `data-startup`과 `morning-drive:*` performance mark를 남긴다.

실행 스크립트는 원본이 제공하는 `VITE_COMPRESSED=1`을 사용한다. 모델·텍스처 파일 자체를 변경하지 않는다.
물리·카메라·식생·조명·셰이더는 원본과 동일하며, 모바일 픽셀 예산은 렌더 해상도에만 영향을 준다.
준비 완료 mark는 출발 입력 등록 시점이다. 원본 라벨의 등장 애니메이션 완료 시점과는 구분한다.

### 2026-11-13 복원 검증

환경: Apple M2 Pro, 32GB, Ego Chromium 156. 데스크톱 CSS 1440×900, DPR 1.5, 캔버스 2160×1350. 캐시를 비활성화했다.
전후 모두 Vite 프로덕션 정적 파일을 Next 개발 서버에서 제공했다. 각 조건 1회 측정이며 로컬 네트워크 결과다.

| 항목                | 압축 적용 전 | 압축 적용 후 |
| ------------------- | -----------: | -----------: |
| 초기 리소스 전송량  |  6,629,935 B |  5,275,910 B |
| GLB 전송량          |  1,735,567 B |    447,647 B |
| 출발 라벨 생성 시점 |     2,522 ms |     2,510 ms |
| 주행 프레임 중앙값  |       8.3 ms |       8.3 ms |
| 주행 프레임 p95     |       9.2 ms |       9.3 ms |

주행은 Enter 출발 후 W 입력, 240개 RAF 간격 중 첫 60개를 제외했다. 시간·계절은 원본 주기를 유지하므로 픽셀 단위 동일 장면 비교는 아니다.
압축 적용 후 최초 주행 측정은 자동 검사와 겹쳐 p95 16.7ms였다. 검사가 끝난 뒤 다시 측정한 값을 표에 썼다. 프레임은 CPU 측 RAF 간격이며 GPU 타이머 측정은 아니다.
전송량은 약 20.4% 줄었지만 이 환경의 로딩 시간과 주행 성능은 사실상 동일하다. 큰 FPS 개선을 확인한 것으로 해석하지 않는다.

별도 Next 프로덕션 서버에서 캐시 없는 재시도 후 준비 완료는 1,719ms였다. 개발 서버와 실행 시점이 달라 직접적인 개선율 비교에는 쓰지 않는다.
모델 요청을 차단해 실패 안내를 확인한 뒤 차단을 해제하고 실제 재시도 버튼으로 준비 완료·출발까지 확인했다.

아이폰 미니 화면 크기(375×812, DPR 3)와 터치를 에뮬레이션했다. 캔버스는 562×1218로, 기존 최대 DPR 2의 750×1624보다 픽셀이 약 44% 적다.
한국어 터치 안내와 터치 출발을 확인했다. 실제 iPhone 12/13 mini, Safari, 발열, 장시간 성능은 미검증이다.

검사: 전체 `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm --filter morning-drive build --webpack`, `origin:verify` 통과.
기존 자동 주행 테스트는 이전 자체 구현을 대상으로 하므로 원본 물리 검증으로 대신하지 않는다. 현재 원본 기반 앱은 위 브라우저 흐름을 별도로 확인했다.
깨끗한 고정 커밋에 001→002 패치 적용도 재현했고, 정적 에셋·물리·카메라·식생 소스의 변경이 없음을 확인했다.
증거 파일은 로컬 `output/verification/morning-drive-restored/`에 보관한다.

### 003-landing-name.patch — DANWOO KIM

출발 구역의 입체 이름만 `DANWOO KIM`으로 교체한다. `LandingArea.setObjects()`에서 물리 등록 전에 이름 모델을 교체하므로 기존 글자에 보이지 않는 충돌체가 남지 않는다.
새 `landingName.js`는 9개 대문자를 구멍과 얕은 모서리 경사가 있는 입체 형상으로 만든다. 외부 폰트·텍스처·모델 다운로드는 추가하지 않는다.
원래 이름의 위치·회전·전체 폭을 기준으로 배치하고, 높이 약 1.45·두께 약 0.44·질량 0.2 및 원본 팔레트 재질을 유지한다. 각 글자의 충돌 크기는 실제 형상 경계로 계산한다.
기존 오브젝트 등록·충돌음·리셋을 그대로 사용한다. 차량·카메라·지형·식생·라이선스와 원작자 표시는 변경하지 않는다.

전후 화면은 개발 서버에서 1440×900/DPR 1.5, 시작 카메라, 낮 주기 0.1·계절 주기 0.375로 고정했다. 계절에 따른 잎은 기존 보간으로 수렴하며, 꽃잎·바람 등의 애니메이션 위상은 다를 수 있다. 실제 실행에서는 원본 시간 주기를 유지한다.
증거: `output/verification/morning-drive-name/before.png`, `after.png`, `collision.png`.

검증: 실제 W 전진 입력 후 새 글자들이 밀려나는 것을 확인했고, 원본 `game.reset()` 실행 후 9개 글자 모두 초기 위치 오차 0.05 이내로 복귀했다.
전체 lint·typecheck·test 및 원본 기반 정적 빌드 통과. 기존 자동 주행 테스트와는 별도로 현재 장면의 충돌·복귀를 브라우저에서 확인했다.
깨끗한 기준 소스에서 001→002→003 패치를 재적용하여 작업본과 일치함을 확인했다.

### 004-boxy-vehicle.patch — 검정 SUV

기본 차량 외형을 각진 SUV로 바꾼다. `VisualVehicle.js`의 기본 모델 선택과 검정 도색만 연결하고, 새 `boxyVehicle.js`에서 차체를 구성한다.
수직에 가까운 창문, 평평한 지붕, 수평 보닛, 원형 헤드램프, 그릴, 도어 경첩·손잡이·발판, 고정 휠 아치와 후면 스페어타이어가 있다.
차체 재질은 원본의 명암·그림자·등장 셰이더를 사용한다. 기본 도색은 짙은 차콜이다. `index.html`의 기본 도색과 보상 순서도 검정/빨강을 교환하여 표시와 실제 선택을 맞춘다. 이미 해금해 선택한 다른 색은 유지한다.

차체 외피 크기(바퀴 제외)는 기존 2.99×1.32×1.89에서 3.07×1.41×1.84로, 비슷한 크기 안에서 실루엣을 바꿨다. 뒤쪽 스페어타이어와 평평한 지붕 때문에 길이·높이는 소폭 늘었다.
물리 충돌체·질량 2.5·바퀴 반경 0.4·축 위치 ±0.9/±0.75와 주행 코드·카메라는 바꾸지 않는다. 기존 타이어·휠·서스펜션을 재사용한다.
브레이크등·후진등·방향지시등은 원본 이름 연결을 유지한다. 부스트 추진과 궤적은 유지하되 기본 차체의 기존 SF 에너지 셀은 새 외형에 포함하지 않는다.
다른 보너스 차량 모델은 원본 경로를 사용한다. 생성한 형상과 전용 재질은 차량 교체 시 해제하고, 공유 바퀴 형상은 해제하지 않는다.

#### 검증 (2026-11-13)

- 낮 주기 0.1·계절 주기 0.375, 동일한 시작 카메라·1440×900/DPR 1.5로 전후 확인. 확대 카메라는 검증 공간에서만 사용한다.
- 차량 메시 30→23개, 삼각형 6,072→9,232개. 추가 모델·텍스처 네트워크 요청은 없다.
- 같은 로드된 장면의 정차 상태에서 외형만 교체해 RAF 간격 측정: 원본 중앙값 16.4ms/p95 17.4ms, 새 차량 16.4ms/p95 17.5ms. 각 300프레임 중 첫 120개 제외. GPU 타이머·장시간 주행 측정은 아니다.
- 실제 전진·조향 입력에서 이동 8.76, 최대 조향 0.5를 확인했다. 제동 시 정지등, 후진 입력 시 후진등이 켜지고, 기존 리셋으로 복귀한다. 물리·카메라 소스는 고정 원본과 동일하다.
- 검증 증거: `output/verification/morning-drive-suv/`의 `before.png`, `black-world.png`, `black-close.png`, `driving.json`, `frames-comparison.json`.

최종 검증: 전체 `pnpm lint`, `pnpm typecheck`, `pnpm test`, `origin:verify`, `origin:build` 통과. 4개 패치를 깨끗한 원본에 순서대로 적용한 결과가 작업본과 일치했다.
빌드된 정적 화면을 기본 `/` 주소에서 확인했다. 아이폰 미니 크기 375×812/DPR 3 에뮬레이션은 562×1218 캔버스에서 오류 없이 렌더됐고 출발 후 월드까지 확인했다. 실물 iPhone·Safari 성능과 발열은 미검증이다.

### 005-danwoo-content.patch — 내 프로젝트와 허브 연결

- `ProjectsArea`: 원래 전시 전환·카메라·인터랙션을 유지하고 허브의 7개 프로젝트, 실제 WebP 썸네일과 링크로 교체한다. 원본 수상 정보는 넣지 않는다.
- `LabArea`: 별도 실험 목록 대신 Danwoo Lab 허브 입구로 사용한다. 상호작용하면 전체 프로젝트 허브가 새 탭으로 열린다. 해당 업적도 허브 입구 사용 1회로 바꾼다.
- `CareerArea`: 원본 경력 텍스처·연도 표시를 개인 소개 패널로 교체한다. 석판의 등장·퇴장 애니메이션은 유지하고 `View Resume`에서 허브에 등록된 이력서를 연다. 경력 연도나 회사 정보는 임의로 만들지 않는다.
- `TimeMachineArea`: `Visit Danwoo Lab`으로 바꾸고 TV 화면도 허브 이미지로 교체한다. 충돌 반응은 유지한다. 지도 표기도 `Danwoo Lab`, `Profile / Resume`, `Lab Portal`로 맞춘다.
- 새 외부 링크는 `noopener,noreferrer`로 연다. 프로젝트 이미지 텍스처에 색 공간·방향·필터를 직접 적용한다.

`scripts/portfolioContent.mjs`가 허브의 `projects.ts`, `profileContent.ts`, 프로젝트 썸네일과 OG 이미지를 읽어 원본 작업 디렉터리에 데이터·에셋을 생성한다. 생성 데이터와 이미지 해시도 빌드 재사용 여부에 포함한다. 허브 데이터 변경은 Morning Drive 재빌드/개발 서버 재시작 시 반영된다. 별도 런타임 API나 중복 수동 목록은 없다.

현재 허브에 게시된 `Unicorn Rush`도 목록에 포함한다. 이 앱의 실제 공개 상태나 프로젝트 목록 선별은 허브에서 관리한다. 원본 SNS·제작 소개는 이 패치 범위 밖이다.

검증: 전체 lint·typecheck·test, 구조 검사, `origin:verify`, 원본 정적 빌드, Next webpack 프로덕션 빌드 통과. 깨끗한 고정 커밋에서 5개 패치를 순서대로 적용해 변경 파일 일치를 확인했다. Turbo dry-run에서 허브 데이터·이미지가 빌드 입력에, `public/origin`이 캐시 출력에 포함되는 것을 확인했다. 같은 콘텐츠를 재동기화해도 생성 파일 수정 시간과 해시가 유지된다.

브라우저에서는 실제 Enter로 전시를 열고 방향키로 7개 프로젝트를 순회하면서 제목·URL·썸네일 로딩과 7/7 업적을 확인했다. Lab 입구와 Lab Portal에서 실제 새 탭으로 `https://lab.danwoo.dev/`, 경력 입구에서 허브의 Google 문서 이력서 URL이 열렸다. 이력서 본문 접근 권한이나 최신 경력 내용은 별도 검증하지 않았다. 기본 `localhost:3000/`에서도 005 패치가 포함된 정적 빌드의 준비 완료·이미지 200 응답을 확인했다. 화면 증거는 `output/verification/morning-drive-content/`에 있다. 이번 변경의 실물 iPhone 검수는 수행하지 않았다.

### 006-free-drive.patch — 기능 정리와 마루부리

월드의 지형·식생·광원·카메라·차량 물리를 유지하며, 개인 콘텐츠와 자유 주행에 필요한 기능으로 정리한다.

- 소셜 링크는 허브의 이력서·블로그·GitHub·SoundCloud와 Lab 입구로 연결한다. 링크 표지판의 글자와 외형만 바꾸고 위치·물리 오브젝트·중앙 조형물은 유지한다. 연결하지 않는 표지판은 장식 기호로 남긴다. 제작 소개와 원작자 크레딧은 이번 교체 대상에서 제외한다.
- 서버 연결, 방명록, 업적과 보상 조건, 누적 플레이 기록, 공동 이벤트를 실행 경로에서 제거한다. 고정 원본의 미사용 모듈 파일은 남아 있지만 게임이 생성하거나 가져오지 않는다. 과거 저장 값을 임의로 삭제하지 않는다.
- 서킷은 현재 주행 시간·체크포인트·완주 반응·재도전을 유지한다. 순위 제출·저장·리셋 시각을 제거하고 기존 기록판은 서킷 안내판으로 사용한다. 하단 Reset 자리는 로컬 장애물을 다시 놓는 기능으로 연결한다.
- 업적 구역의 폭포·조형물, 제단의 로컬 반응, 쿠키·볼링·상자 반응은 유지한다. 볼링 스트라이크 소리는 업적 모듈과 분리해 직접 등록한다. 자연 날씨는 유지하고 서버 공동 이벤트만 제거한다.
- 설정에서 여섯 도색을 자유롭게 고른다. 도색 선호만 별도 키에 저장하며 허용된 이름을 검증한다. 이는 게임 기록 저장과 구분한다.
- 로컬 마루부리 Regular/Bold를 메뉴·안내·캔버스 텍스트에 적용한다. 캔버스 글자는 글꼴 로딩을 기다린 뒤 그린다. 두 WOFF2는 합계 약 587KB이며 외부 Google Fonts 요청을 제거했다. 라이선스도 함께 배포한다.
- 메뉴 미리보기는 현재 DANWOO KIM·검정 SUV 장면의 WebP(약 50KB)로 바꾼다. 작은 화면에서 메뉴를 열면 로고·하단 크레딧을 숨겨 조작부와 겹치지 않게 한다. 메뉴를 닫으면 다시 표시한다.

#### 검증과 남은 범위

전체 `pnpm lint`, `pnpm typecheck`, `pnpm test` 통과 후 변경 스크립트에 대해 앱 lint를 재확인했다. 원본 정적 빌드와 Next webpack 프로덕션 빌드가 통과했다. 깨끗한 고정 커밋에서 6개 패치를 순서대로 적용하여 소스 45개가 작업본과 일치하는 것을 확인했다. 최종 이미지 최적화 후에도 `origin:verify`와 정적 빌드를 확인한다.

브라우저에서 마루부리 두 굵기의 로딩, 도색 변경·복귀, 제거 대상 인스턴스 부재, 서킷 완주 창과 실제 재도전 버튼을 확인했다. 서킷 완주는 상태 전환을 직접 호출한 검사이며 이번 작업에서 전체 코스를 운전해 완주한 검사는 아니다. 링크 구역과 서킷 안내판은 화면으로 확인했다. 개인 링크의 원격 페이지 내용·권한은 재검증하지 않았다.

아이폰 미니 크기 375×812/DPR 3에서 캔버스 562×1218, 터치 출발·주행·손 해제, 가로 812×375 회전, 메뉴 한글과 가로 넘침을 확인했다. 두 손가락 줌 입력도 확인했지만 반복 입력·백그라운드 복귀 검수는 남아 있다. 실제 iPhone 12/13 mini Safari·발열·장시간 프레임과 메모리는 미검증이다. 데스크톱 GPU에서 측정한 프레임은 실기기 성능으로 해석하지 않는다.

기본 3000번 주소에서도 빌드된 화면의 글꼴·메뉴를 확인했다. 증거는 `output/verification/morning-free-drive/`에 있다. 기존 자동 주행 테스트는 이전 재구현 대상이므로 이번 원본 기반 기능 검증을 대신하지 않는다. 미사용 원본 의존성의 `eval` 관련 빌드 경고는 남아 있으며, 이번 변경에 실행 코드 평가를 추가하지 않았다.

375×812에서 W 입력 중 RAF 180개 중 첫 30개를 제외한 표본은 중앙값 8.3ms, p95 9.2ms였다. Vite 프로덕션 정적 파일을 Next 개발 서버 3000번에서 제공했고 데스크톱 GPU로 측정했다. 짧은 1회 표본이며 실제 아이폰 성능·장시간 안정성·개선율을 뜻하지 않는다. 측정 원본은 `mobile-frame-sample.json`이다.
