Streaming SSR은 **HTML을 한 번에 보내지 않고 준비된 부분부터 점진적으로 전송**하는 방식이고, React 18의 Suspense가 그 경계를 정의합니다.

### **기존 SSR의 문제**

서버가 **모든 데이터를 다 기다린 뒤에야** 완성된 HTML을 한 번에 보냅니다. 가장 느린 데이터 하나가 페이지 전체의 첫 응답을 지연시킵니다.

### **Streaming SSR의 동작**

느린 부분을 Suspense로 감싸두면:

- 서버는 Suspense **바깥 콘텐츠와 fallback(스켈레톤)을 즉시 전송**하고, 브라우저는 바로 그리기 시작합니다 — TTFB와 FCP가 개선됩니다.
- 느린 데이터가 준비되면 그 부분의 HTML **청크를 이어서 전송**하고, 브라우저가 fallback을 실제 콘텐츠로 교체합니다.
- hydration도 통째로 하지 않고 **사용자가 상호작용하는 영역부터** 진행합니다(선택적 하이드레이션).

### **Suspense의 역할**

Suspense 경계가 곧 **스트리밍의 단위**입니다. "여기까지는 먼저 보여도 되고, 이 안쪽은 늦어도 된다"를 컴포넌트 트리 위에 선언하는 것입니다.

### **Next.js에서는**

App Router의 **`loading.tsx`가 자동으로 그 세그먼트의 Suspense 경계**를 만들어 줍니다. 더 세밀하게 나누고 싶으면 페이지 안에서 직접 Suspense로 감싸면 됩니다. 느린 API 하나가 전체 페이지를 막는 문제가 이 구조로 해결됩니다.
