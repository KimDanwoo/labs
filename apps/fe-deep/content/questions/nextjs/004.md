App Router는 **확장된 fetch API의 옵션으로** 데이터 캐싱을 제어합니다.

### **fetch 캐싱 옵션**

- **캐시 사용** — 빌드 시점 데이터로 고정되어 SSG처럼 동작합니다.
- **캐시 안 함(no-store)** — 요청마다 새로 가져와 SSR처럼 동작합니다.
- **시간 기반 재검증(revalidate)** — 지정한 시간이 지나면 백그라운드에서 갱신되어 ISR처럼 동작합니다.

### **온디맨드 재검증**

시간 주기가 아니라 **데이터가 실제로 바뀐 순간** 갱신하고 싶으면, 데이터를 변경하는 Server Action이나 Route Handler에서 `revalidatePath`(경로 기준)나 `revalidateTag`(태그 기준)를 호출합니다. 글을 수정하면 그 글 페이지만 즉시 갱신하는 식입니다.

### **알아둘 것**

- 같은 렌더링 중 **동일한 fetch 요청은 자동으로 중복 제거**됩니다. 여러 컴포넌트가 같은 데이터를 각자 가져와도 요청은 한 번입니다.
- Server Component에서는 fetch 없이 **DB 쿼리를 직접** 할 수도 있고, fetch가 아닌 데이터는 `unstable_cache`로 캐싱할 수 있습니다.

### **버전 주의 — Next.js 15의 기본값 변경**

14까지는 fetch가 **기본적으로 캐시**됐지만, **15부터는 기본이 캐시 안 함**으로 바뀌었습니다. 캐싱을 원하면 `force-cache`나 `revalidate`를 명시해야 합니다. "왜 데이터가 안 바뀌지/왜 매번 요청하지"의 상당수가 이 기본값 차이에서 나옵니다.
