세 가지 모두 **HTML을 언제 만드느냐**의 차이입니다.

### **SSR (Server-Side Rendering)**

**매 요청마다** 서버에서 HTML을 생성합니다. 항상 최신 데이터를 보여줄 수 있지만, 요청마다 서버 작업이 필요해서 첫 바이트 응답(TTFB)이 정적 방식보다 느리고 서버 비용이 듭니다.

### **SSG (Static Site Generation)**

**빌드 시점에** HTML을 미리 만들어 둡니다. 완성된 파일을 CDN에서 그대로 내려주므로 가장 빠르지만, 내용을 바꾸려면 다시 빌드해야 합니다. 데이터가 자주 변하지 않는 페이지에 적합합니다.

### **ISR (Incremental Static Regeneration)**

SSG처럼 정적으로 서빙하되, **설정한 주기(revalidate)가 지나면 백그라운드에서 페이지를 다시 생성**합니다. 재배포 없이 내용이 갱신되는 SSG와 SSR의 절충안입니다.

### **App Router에서의 표현**

App Router에는 페이지 단위 함수 대신 **fetch 캐싱 옵션과 라우트 설정으로** 표현합니다 — 캐시하면 SSG처럼, `revalidate`를 주면 ISR처럼, 동적 렌더링을 강제하면 SSR처럼 동작합니다.

### **선택 기준**

- 블로그·문서·랜딩처럼 정적 콘텐츠 → **SSG**
- 개인화되거나 요청 시점 데이터가 필요한 화면 → **SSR**
- 자주 갱신되지만 실시간일 필요는 없는 목록 → **ISR**
