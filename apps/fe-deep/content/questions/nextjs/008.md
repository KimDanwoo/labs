Route Handlers는 **App Router에서 API 엔드포인트를 만드는 방식**입니다. `app` 디렉토리 안에 `route.ts` 파일을 두고, 기존 API Routes(`pages/api`)를 대체합니다.

### **주요 차이**

- **메서드 분리** — 기존에는 하나의 handler 안에서 `req.method`로 분기했지만, Route Handlers는 **GET, POST 같은 HTTP 메서드 이름의 함수를 각각 export**합니다. 코드가 메서드별로 자연스럽게 나뉩니다.
- **표준 Web API 기반** — Node.js 고유의 req/res 객체 대신 **웹 표준 Request/Response**를 사용합니다. 표준 기반이라 Edge Runtime에서도 동일하게 동작합니다.
- **캐싱** — 기존 API Routes에는 캐싱 개념이 없었지만, Route Handlers의 GET은 fetch와 같은 캐싱 체계에 참여할 수 있습니다. 단, **Next.js 15부터 GET도 기본적으로 캐시하지 않는 쪽**으로 바뀌었습니다.
- **위치** — 페이지와 같은 트리에 두므로 관련 화면 근처에 콜로케이션할 수 있습니다.

### **Server Actions와의 역할 구분**

Server Actions가 나온 뒤로 **자기 앱 내부의 데이터 변경**은 Route Handler 없이 처리할 수 있게 됐습니다.

그래도 Route Handler가 필요한 곳이 있습니다 — **외부 서비스가 호출하는 Webhook**, 다른 클라이언트(모바일 앱 등)에 제공하는 API, OAuth 콜백, 파일 다운로드처럼 **HTTP 엔드포인트 자체가 필요한 경우**입니다. "내부 변경은 Server Actions, 외부 접점은 Route Handlers"로 나누면 깔끔합니다.
