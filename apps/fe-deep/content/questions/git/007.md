git bisect는 **이진 탐색**으로 버그를 도입한 커밋을 빠르게 찾아냅니다.

**사용법:**
```bash
# 1. bisect 시작
git bisect start

# 2. 현재(버그 있음)를 bad로 표시
git bisect bad

# 3. 버그 없던 커밋을 good으로 표시
git bisect good abc123

# 4. Git이 중간 커밋을 체크아웃 → 테스트 후 good/bad 판정
git bisect good  # 또는 git bisect bad

# 5. 반복하면 원인 커밋 특정
# "abc456 is the first bad commit"

# 6. 종료
git bisect reset
```

**자동화:**
```bash
# 테스트 스크립트로 자동 판별
git bisect start HEAD abc123
git bisect run npm test
# 테스트 성공(exit 0) → good, 실패(exit 1) → bad
```

**활용 시나리오:**
- 특정 시점 이후 발생한 성능 저하 원인 추적
- 회귀 버그(regression) 원인 커밋 특정
- 100개 커밋 중 원인 찾기: 최대 7회(log₂100) 테스트로 특정

**팁:** bisect 전에 재현 가능한 테스트 케이스를 먼저 작성하면 자동화 가능
