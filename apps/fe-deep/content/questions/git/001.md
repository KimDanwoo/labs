둘 다 브랜치를 통합하는 방법이지만, 히스토리가 달라집니다.

```bash
# Merge: 새로운 병합 커밋 생성
git checkout main
git merge feature  # 병합 커밋 생성

# Rebase: 커밋을 재배치 (선형 히스토리)
git checkout feature
git rebase main    # feature의 커밋을 main 위로 이동
git checkout main
git merge feature  # fast-forward
```

| 특성 | Merge | Rebase |
|------|-------|--------|
| 히스토리 | 병합 커밋 포함 (비선형) | 깔끔한 선형 히스토리 |
| 원본 커밋 | 유지 | 새 커밋으로 재작성 |
| 충돌 해결 | 1회 | 각 커밋마다 |
| 안전성 | 원본 유지 | 공유 브랜치에서 위험 |

- **Merge**: 공유 브랜치(main)에 통합할 때 사용
- **Rebase**: 개인 작업 브랜치를 최신 상태로 업데이트할 때 사용
- 이미 push된 커밋은 rebase하지 않는 것이 원칙입니다.
