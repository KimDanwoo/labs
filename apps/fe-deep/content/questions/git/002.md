두 가지 대표적인 Git 브랜치 전략입니다.

**Git Flow:**
```
main ───────────────── 배포
develop ──────────── 개발 통합
  feature/xxx ──── 기능 개발
  release/1.0 ──── 릴리스 준비
  hotfix/xxx ───── 긴급 수정
```

**GitHub Flow:**
```
main ───────────────── 항상 배포 가능
  feature/xxx ──── 기능 개발 → PR → 코드리뷰 → main 머지
```

- **Git Flow**: 릴리스 주기가 있는 프로젝트에 적합 (모바일 앱 등)
- **GitHub Flow**: CI/CD 기반의 지속적 배포에 적합 (웹 서비스)
- 대부분의 웹 프로젝트에서는 GitHub Flow가 더 적합합니다.
- Trunk-Based Development도 최근 많이 사용되는 전략입니다.
