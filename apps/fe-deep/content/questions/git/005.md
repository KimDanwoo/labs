Monorepo는 여러 프로젝트를 하나의 저장소에서 관리하는 전략입니다.

**장점:**
- 코드 공유 용이 (공통 컴포넌트, 유틸)
- 일관된 도구/설정 관리
- 원자적 변경 (여러 패키지 동시 수정 후 단일 커밋)
- 의존성 버전 통일

**단점:**
- 저장소 크기 증가
- CI/CD 복잡성 (변경된 패키지만 빌드/테스트 필요)
- 접근 권한 관리 어려움

**도구 비교:**
| 도구 | 특징 | 장점 |
|------|------|------|
| **Turborepo** | 캐싱 기반 빌드 | 빠름, 설정 간단, Vercel 통합 |
| **Nx** | 풀 기능 빌드 시스템 | 의존성 그래프, 생성기 |
| **pnpm workspace** | 패키지 매니저 내장 | 디스크 효율, 빠른 설치 |
| **Lerna** | 레거시 (Nx에 통합) | 버전 관리, 배포 |

**pnpm workspace 기본 설정:**
```yaml
# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'
```

- Turborepo + pnpm 조합이 현재 가장 인기
- Next.js 프로젝트는 Turborepo와 자연스럽게 통합
