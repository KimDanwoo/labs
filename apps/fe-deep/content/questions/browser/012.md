브라우저는 Mark-and-Sweep 알고리즘으로 메모리를 관리합니다.

**Mark-and-Sweep:**
1. Root(전역 객체, 실행 스택)에서 도달 가능한 모든 객체 마킹
2. 마킹되지 않은 객체를 메모리에서 해제

**프론트엔드 메모리 누수 원인:**
```javascript
// 1. 해제하지 않은 이벤트 리스너
element.addEventListener('click', handler);
// 컴포넌트 해제 시 removeEventListener 필수

// 2. 해제하지 않은 타이머
const id = setInterval(update, 1000);
// clearInterval(id) 필요

// 3. 클로저가 유지하는 큰 객체
function createLeak() {
  const hugeData = new Array(1000000);
  return () => hugeData.length; // hugeData 참조 유지
}

// 4. 분리된 DOM 노드 (Detached DOM)
const div = document.createElement('div');
document.body.appendChild(div);
document.body.removeChild(div);
// 변수 div가 참조를 유지 → GC 안 됨
```

**탐지 방법:**
1. Chrome DevTools → Memory 탭 → Heap Snapshot
2. Timeline에서 메모리 그래프 모니터링 (계속 증가하면 누수)
3. Performance Monitor에서 JS Heap Size 관찰
4. `performance.memory` API (Chrome)

**React에서의 방지:**
- useEffect cleanup 함수에서 리스너/타이머 해제
- AbortController로 진행 중인 fetch 취소
- WeakRef/WeakMap으로 약한 참조 사용
