CORS는 브라우저의 동일 출처 정책(Same-Origin Policy)을 우회하여 다른 출처의 리소스에 접근할 수 있도록 허용하는 메커니즘입니다.

**동일 출처**: 프로토콜 + 호스트 + 포트가 모두 같아야 함

```
https://example.com:443  ← 출처(Origin)
  ↕ 같은 출처
https://example.com/api

  ✗ 다른 출처
http://example.com       (프로토콜 다름)
https://api.example.com  (호스트 다름)
https://example.com:8080 (포트 다름)
```

**서버 측 CORS 헤더 설정:**
```
Access-Control-Allow-Origin: https://frontend.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Credentials: true
```

**Preflight 요청**: PUT, DELETE 등 "단순하지 않은" 요청은 OPTIONS 메서드로 사전 요청을 보냅니다.

- CORS 에러는 브라우저에서만 발생하며, 서버 간 통신에서는 발생하지 않습니다.
- 개발 시 Next.js의 rewrites나 프록시 설정으로 우회할 수 있습니다.
