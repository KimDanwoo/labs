UI 아키텍처 패턴은 관심사의 분리 방식이 다릅니다.

**MVC (Model-View-Controller):**
- Controller가 사용자 입력을 받아 Model 업데이트
- Model이 변경되면 View가 갱신
- View와 Model이 직접 통신 가능
- 예: Express.js (백엔드)

**MVP (Model-View-Presenter):**
- Presenter가 View와 Model 사이의 중재자
- View는 Presenter만 알고, Model은 모름
- View ↔ Presenter ↔ Model
- 테스트 용이 (Presenter 단위 테스트)

**MVVM (Model-View-ViewModel):**
- ViewModel이 데이터 바인딩으로 View와 자동 동기화
- View ←바인딩→ ViewModel ↔ Model
- 예: Vue.js (양방향 바인딩), Angular

| 패턴 | 통신 | 특징 | 프레임워크 |
|------|------|------|----------|
| MVC | 삼각 | 단순, 대규모에서 복잡 | Express |
| MVP | 선형 | 테스트 용이 | Android |
| MVVM | 바인딩 | 선언적, 자동 동기화 | Vue, Angular |

**React의 위치:**
React는 특정 패턴을 강제하지 않지만 **단방향 데이터 흐름**으로 Flux/Redux 패턴이 자연스러움. MVVM보다는 함수형 접근(UI = f(state))에 가까움.
