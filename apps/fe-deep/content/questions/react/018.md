React 18의 동시성(Concurrency)은 **렌더링을 중단·재개·폐기할 수 있게 만든 렌더러의 근본적인 변화**입니다. 여러 작업을 물리적으로 동시에 실행하는 것이 아니라(JS는 여전히 싱글 스레드), **렌더링에 우선순위를 두고 급한 일이 오면 하던 렌더를 양보**하는 방식입니다.

### **이전과 무엇이 다른가**

기존(Legacy) 모드에서 렌더링은 한번 시작하면 끝까지 **중단할 수 없었습니다.** 큰 트리를 렌더하는 동안 사용자 입력이 밀렸습니다. Concurrent 모드에서는 렌더 도중 더 급한 업데이트가 들어오면 **진행 중인 작업을 버리고 급한 것부터** 처리합니다.

### **핵심 기능**

- **useTransition** — 상태 업데이트를 감싸 "급하지 않다"고 표시합니다. 무거운 목록 갱신 때문에 입력이 버벅이는 문제를 해결하고, isPending으로 지연 상태를 표시할 수 있습니다.
- **useDeferredValue** — 값의 지연된 사본을 만듭니다. setter에 접근할 수 없이 **props로 받은 값**일 때 씁니다. 디바운스와 달리 고정 시간을 기다리지 않고 **기기 성능에 적응**하며, 새 입력이 오면 진행 중이던 렌더를 즉시 폐기합니다.
- **Automatic Batching** — 17까지는 이벤트 핸들러 안에서만 상태 업데이트가 묶였지만, 18부터는 setTimeout·Promise 안에서도 자동으로 묶여 리렌더 횟수가 줄어듭니다. 즉시 반영이 필요하면 flushSync가 탈출구입니다.
- **Streaming SSR + Suspense** — 서버가 준비된 부분부터 HTML을 흘려보내고 늦은 부분은 나중에 채웁니다. 사용자가 상호작용한 영역부터 hydrate하는 **선택적 하이드레이션**과 결합되며, Next.js App Router의 loading.tsx가 이 위에 올라가 있습니다.
- **useSyncExternalStore** — 외부 store를 tearing(같은 렌더 안에서 서로 다른 값을 보는 현상) 없이 구독합니다. Zustand·Redux 내부에서 사용합니다.
- **useId** — 서버·클라이언트에서 일치하는 안정적인 ID를 만들어 하이드레이션 불일치를 방지합니다.

### **활성화와 주의점**

`createRoot`를 쓰면 동시성 기반이 켜지지만 **자동으로 빨라지는 게 아니라**, transition 등으로 "무엇이 급하지 않은지"를 개발자가 알려줘야 효과가 납니다.

렌더가 중단·재실행될 수 있으므로 **렌더 함수는 순수해야 합니다.** StrictMode가 개발 모드에서 이중 렌더를 하는 이유가 이 문제를 잡기 위해서입니다.

### **한 줄 요약**

동시성은 렌더링을 **중단 가능**하게 만들어 우선순위를 부여하는 것이고, useTransition·useDeferredValue는 "이건 급하지 않다"고 표시하는 수단입니다.
