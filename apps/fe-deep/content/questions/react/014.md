웹 접근성은 스크린 리더 사용자, 키보드만 쓰는 사용자를 포함한 **모든 사용자가 동등하게 서비스를 쓸 수 있게 하는 것**입니다. React에서의 핵심 전략은 다음과 같습니다.

### **1. 시맨틱 HTML 우선**

`div`에 onClick을 붙이는 대신 `button`, `a`, `input` 같은 **네이티브 요소**를 씁니다. 키보드 포커스, Enter/Space 동작, 스크린 리더 인식이 공짜로 따라옵니다. ARIA를 붙이기 전에 맞는 태그가 있는지 먼저 찾는 것이 원칙입니다.

### **2. 포커스 관리**

SPA는 화면이 바뀌어도 브라우저가 포커스를 옮겨주지 않으므로 직접 관리해야 합니다.

- 모달이 열리면 포커스를 모달 안으로 이동시키고, 닫히면 원래 위치로 되돌립니다.
- 모달이 열려 있는 동안 포커스가 바깥으로 나가지 않게 **focus trap**을 적용합니다.
- Escape로 닫기 같은 키보드 인터랙션을 지원합니다.

### **3. ARIA 속성**

시맨틱 태그로 부족한 부분에 `role`, `aria-label`, `aria-modal`, `aria-live`(동적 콘텐츠 알림) 등을 사용합니다. 단, **잘못 쓴 ARIA는 없는 것보다 나쁘므로** 필요한 곳에만 정확히 씁니다.

### **4. 시각적 기준**

색상 대비는 WCAG AA 기준(일반 텍스트 4.5:1)을 지키고, 색만으로 정보를 전달하지 않습니다.

### **5. 검증 도구와 테스트**

- `eslint-plugin-jsx-a11y`로 코드 단계에서 정적 검사
- Lighthouse·axe로 런타임 검사
- 최종적으로는 VoiceOver(Mac)나 NVDA(Windows) 같은 **실제 스크린 리더로 직접 확인**하는 것이 가장 확실합니다.
