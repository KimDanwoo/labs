Virtual DOM은 UI의 상태를 JavaScript 객체 형태의 트리로 표현한 것입니다. 자바스크립트 **객체 형태의 트리로 표현**한 것입니다. 
React에서는 **상태나 props가 변경**되면 실제 DOM을 바로 수정하는 것이 아니라, 먼저 변경된 상태를 기준으로 **새로운 Virtual DOM을 생성**합니다.

그다음 이전 Virtual DOM과 새로 만들어진 Virtual DOM을 비교하는 **Diffing 과정을 수행**합니다. 이 과정에서 요소의 타입이 같은지 확인하고, 같은 요소라면 속성이나 자식 요소 중 어떤 부분이 변경되었는지를 비교합니다. 리스트의 경우에는 key를 기준으로 기존 요소와 새 요소의 관계를 판단합니다.

이렇게 비교한 결과를 바탕으로 React는 실제로 어떤 부분을 변경해야 하는지 결정하는 **Reconciliation 과정을 거칩니다.** 이후 **Commit 단계에서 계산된 변경사항만 실제 DOM에 반영**합니다.

실제 DOM이 변경된 이후에는 브라우저가 필요에 따라 Layout이나 Paint 같은 렌더링 작업을 수행합니다.

따라서 Virtual DOM을 사용하는 이유는 **실제 DOM보다 무조건 빠르기 때문이라기보다**는, **상태가 변경될 때마다 개발자가 직접 DOM을 조작하지 않아도 React가 변경사항을 계산하고 필요한 부분만 실제 DOM에 반영**할 수 있도록 하기 위해서입니다.


- **성능 최적화**: 직접 DOM을 조작하는 것보다 batch 업데이트가 가능하여 효율적입니다.
- **선언적 프로그래밍**: 개발자는 "어떻게 DOM을 변경할지"가 아니라 "UI가 어떤 상태여야 하는지"만 선언하면 됩니다.
- **크로스 플랫폼**: React Native 등 다른 플랫폼으로의 확장이 가능합니다.
- React 18의 Concurrent Features는 이 과정을 더욱 최적화합니다.
