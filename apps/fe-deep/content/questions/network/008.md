Preflight는 실제 요청 전에 서버가 CORS를 허용하는지 확인하는 **OPTIONS 요청**입니다.

**Preflight가 발생하는 조건:**
- GET/HEAD/POST 외의 메서드 (PUT, DELETE, PATCH)
- Content-Type이 application/json 등 비단순 타입
- 커스텀 헤더 (Authorization 등)

**흐름:**
```
1. 브라우저 → OPTIONS /api/users (Preflight)
   Origin: https://frontend.com
   Access-Control-Request-Method: DELETE
   Access-Control-Request-Headers: Authorization

2. 서버 → 200 OK
   Access-Control-Allow-Origin: https://frontend.com
   Access-Control-Allow-Methods: GET, POST, DELETE
   Access-Control-Allow-Headers: Authorization
   Access-Control-Max-Age: 86400  # 캐싱 (24시간)

3. 브라우저 → DELETE /api/users (실제 요청)
```

**최적화:**
- `Access-Control-Max-Age`로 Preflight 캐싱 (반복 요청 방지)
- 단순 요청(Simple Request) 조건을 맞추면 Preflight 생략
- 같은 출처(same-origin) 요청은 CORS 자체가 불필요

**Next.js에서:**
- API Route/Route Handler에서 CORS 헤더 직접 설정
- `next.config.js`의 `headers()`에서 설정
- Middleware에서 동적 CORS 처리
