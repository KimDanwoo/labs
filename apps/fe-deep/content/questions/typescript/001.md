둘 다 타입을 정의하는 데 사용되지만, 몇 가지 중요한 차이가 있습니다.

```typescript
// interface: 선언 병합(declaration merging) 가능
interface User {
  name: string;
  age: number;
}
interface User {
  email: string; // 기존 User에 병합됨
}

// type: 유니온, 인터섹션, 유틸리티 타입에 유리
type Status = 'active' | 'inactive'; // 유니온 타입
type UserWithRole = User & { role: string }; // 인터섹션
type Nullable<T> = T | null; // 제네릭 타입 별칭
```

| 특성 | interface | type |
|------|-----------|------|
| 선언 병합 | O | X |
| extends | O | & (인터섹션) |
| 유니온 타입 | X | O |
| 매핑된 타입 | X | O |
| implements | O | O |

- **interface**: 객체의 형태를 정의할 때, 특히 라이브러리 API 타입에 권장
- **type**: 유니온, 튜플, 매핑 타입 등 복잡한 타입 조합에 사용
- 팀 컨벤션에 따라 선택하되, 일관성을 유지하는 것이 중요합니다.
