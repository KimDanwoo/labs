TypeScript에서 상수를 정의하는 여러 방법이 있으며, 각각 장단점이 있습니다.

```typescript
// 1. enum: 런타임에 객체로 존재
enum Direction {
  Up = 'UP',
  Down = 'DOWN',
}
// 컴파일 후 JavaScript 객체가 생성됨

// 2. const enum: 컴파일 시 인라인으로 치환 (번들 크기 감소)
const enum Status {
  Active = 'ACTIVE',
  Inactive = 'INACTIVE',
}
const s = Status.Active; // 컴파일 후: const s = "ACTIVE"

// 3. as const: 리터럴 타입으로 추론
const COLORS = {
  Red: '#ff0000',
  Blue: '#0000ff',
} as const;

type Color = typeof COLORS[keyof typeof COLORS];
// '#ff0000' | '#0000ff'
```

- **enum**: 런타임 코드가 생성되므로 번들 크기 증가. 양방향 매핑(숫자 enum) 가능.
- **const enum**: 컴파일 시 인라인 치환되어 번들이 작아짐. 단, 일부 빌드 도구와 호환성 이슈.
- **as const**: 가장 권장되는 패턴. 추가 코드 없이 타입 안전성 확보.
- 현대 TypeScript에서는 `as const` 객체를 선호하는 추세입니다.
