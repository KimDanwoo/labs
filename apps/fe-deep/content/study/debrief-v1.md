# 되물음을 신호로 읽기

## 키워드

```text
두 번 물으면 답이 안 나온 것
세 번째 시도 금지
질문 확인 후 침묵
```

## 답변

면접관이 같은 걸 두 번 이상 물으면 **원하는 답이 안 나왔다는 신호**다. 흥미가 있어서 파는 게 아니라, 힌트를 주면서 기다리는 중이다.

이때 할 일은 **세 번째 답을 시도하는 게 아니라 질문을 확인하는 것**이다.

> 제가 질문을 다르게 이해한 것 같은데, ○○을 말씀하시는 걸까요?

**묻고 나서 대답을 듣는다.** 되묻기의 절반은 물음표 뒤의 침묵이다.

## 실제 기록

이번 면접에서 되물음이 세 구간에 있었고, 세 구간 다 감지하지 못했다.

| 구간 | 되물음 | 무슨 일 |
| --- | --- | --- |
| 사주 부동산 08:35–12:35 | **6회** | 같은 내용을 4분 동안 네 번 반복 |
| A/B 지표 19:19–19:57 | **3회** | 지표를 물었는데 세 번 다 차트 종류로 답 |
| 리포트 23:07–23:34 | 1회 | "획기적"을 되물었는데 동어반복으로 답 |

26:17에는 되묻긴 했다. 그런데 **면접관 대답을 듣지 않고** 바로 시멘틱 URL 얘기로 들어가서 27:09에 정정당했다. 되묻는 척하고 추측대로 답한 셈이다.

## 꼬리

### 질문을 다시 확인하면 감점 아닌가요?

키워드: 엉뚱한 답, 4분, 확인 한 문장

아니다. 엉뚱한 답을 4분 하는 것보다 확인 한 문장이 훨씬 낫다. 이번 면접의 사주 구간이 그 4분이었다.

### 확인했는데도 못 알아들으면요?

키워드: 아는 범위 선언, 정직

거기서 아는 범위를 선언하고 끝낸다. "제가 이해한 범위에서 말씀드리면 ○○입니다. 방향이 다르면 말씀해 주세요."

# 결론을 앞으로 끌어내는 문장 구조

## 키워드

```text
우선은 → 금지
첫 문장은 질문에 대한 직접 답
한 답변 한 논점
```

## 답변

**"우선은"으로 답을 시작하지 않는다.** 금지어는 이거 하나면 된다.

이건 단순 말버릇이 아니라 **문장 구조를 결정하는 단어**다. "우선은"으로 열면 문법적으로 뒤에 나열이 와야 해서, 결론이 앞으로 나올 수가 없다. "첫 문장은 결론" 규칙과 이 단어는 물리적으로 양립하지 않는다.

이 하나를 막으면 첫 문장이 강제로 결론이 된다.

## 나쁜 예 — 실제 발화 12:35

> 네 그래서 이제 사용자가 원하는 위치 기반을 어느 정도 받아가지고 그에 맞게 어느 정도 사주와 융합할 수 있는 그런 부동산을 추천하는 게 저희 목표였습니다.

같은 내용을 결론부터:

> 목표는 예산과 희망 지역을 먼저 확정하고, 사주 정보는 순위를 매기는 데만 쓰는 것이었습니다.

## 실제 기록

30분 동안 **"우선은" 14회**, 대부분 답변의 첫 단어였다.
06:12 · 06:41 · 07:04 · 07:51 · 08:35 · 09:22 · 13:17 · 15:40 · 21:57 · 22:41 · 27:09 · 28:47 · 30:04 …

나머지 말버릇은 신경 쓰지 않는다. 여섯 개를 동시에 의식하면 인지부하가 늘어서 더 끊긴다. **filler는 원인이 아니라 증상이고, 문장을 짧게 끝내면 자동으로 준다.**

## 꼬리

### `~것 같습니다`도 없애야 하나요?

키워드: 의견과 사실 구분, hedging, 정직함

구분해야 한다. **의견**을 물었으면 "~라고 생각합니다"가 맞다. 하지만 **불확실한 사실**에는 "~것 같습니다"가 오히려 정직한 표현이다.

싸잡아 지우면 아는 척하는 사람이 된다. "모르는 걸 억지로 아는 척하지 않는다"는 강점이 이 표현으로 나타나기 때문이다.

### 30~60초 규칙을 기계적으로 지키면 되나요?

키워드: 시간 아닌 논점 수, 사실 확인 1개, 경험 2개

시간이 아니라 **논점 수**로 잡는다. 사실 확인 질문은 논점 하나, 경험·설계 질문은 둘까지. 그 이상은 꼬리질문 몫이다.

"본인이 주도한 프로젝트를 설명해달라"에 40초는 오히려 성의 없어 보인다.

# A/B — 차트가 아니라 지표로 답한다

## 키워드

```text
노출 대비 클릭률
전환까지 이어지는지
클릭률만 올랐으면 성공 아님
막대, 원형 아님
```

## 답변

지표를 물었는데 차트 종류로 답하면 세 번까지 되묻는다. **이 답은 통째로 외운다.**

> CTA 실험이라면 노출 대비 클릭률을 1차 지표로 보고, 클릭 이후 문의나 전환까지 이어지는지를 함께 봅니다. 클릭률만 올랐는데 전환이 그대로면 성공으로 보지 않습니다.

형태를 물으면:

> 두 그룹 비율 비교라 막대가 맞다고 생각합니다. 원형 차트는 이 비교엔 안 씁니다.

## 실제 기록

19:19 → 바 차트 / 19:36 → "명확하게 볼 수 있는 형태면 좋을 것 같은데 네 그렇습니다" / 19:57 → 원형 차트 퍼센트.

세 번 다 차트로 답했다. 그리고 **두 그룹 비율 비교에 원형 차트는 쓰지 않는다** — 데이터를 보는 사람 앞에서 나오면 추가 감점이다.

19:36의 "네 그렇습니다"는 할 말이 없는데 문장을 닫아야 해서 나온 소리다. 차라리 "지표 쪽을 여쭤보시는 거면 다시 말씀드리겠습니다"가 나았다.

## 확인 필요

> ✍️ **미확인(2026-08-31)** — 13:17에는 "Amplitude로 사용자를 나눴다", 14:52에는 "쿼리스트링을 붙여 테스트했다"고 답해서 전사본 안에서 충돌한다. 실제 분배는 Amplitude, 쿼리스트링은 QA 강제 진입용일 가능성이 높지만 **확인되지 않았다.** 확인해서 한 문장으로 정리해두지 않으면 다음 면접에서 또 걸린다.

## 꼬리

### 깜빡임은 왜 생기나요?

키워드: 플래그 확정 시점, 첫 렌더, 상태 동기화

플래그가 늦게 확정되면 A가 먼저 그려졌다가 B로 바뀐다. 그래서 첫 렌더에 확정되도록 만들었다.

15:40에 "클라이언트 상태와 동기화되는 과정에서"라고 답했는데 방향은 맞지만 얕다. SSR·CSR 경계, 플래그 fetch 타이밍, hydration 중 **실제로 어디였는지**를 확인해두면 좋다.

### 성공 기준을 미리 정해두나요?

키워드: 분자 분모, 최소 기간, 중단 기준

지금이라면 시작 전에 분자·분모, 최소 기간, 중단 기준을 먼저 합의하고 들어간다. 구현하는 사람이 분모를 알아야 노출 이벤트를 제대로 심을 수 있다.

# 오너십은 긋되 덮지 않는다

## 키워드

```text
경계 긋고 멈춤
이동할 문장 없으면 멈춤
덮으면 앞말까지 무효
```

## 답변

역할이 작았던 일을 물으면 **정확히 긋고 거기서 끝낸다.**

> 실험 설계와 지표 해석은 마케터·기획자가 주도했고, 저는 구현과 방향 논의에 참여했습니다.

**이 문장 뒤에 아무것도 붙이지 않는다.**

## 핸드북 v1 보정

> ✍️ **보정(2026-08-31)** — 핸드북 v1의 A/B 항목에는 *"1문장만 말하고 멈추면 침묵이 생기고 면접관이 그 침묵을 채운다. 인정은 짧게, 이동은 빠르게"*라고 적혀 있다. 의도는 **인정 → 내가 한 일 → 지금이라면**으로 이동하라는 것이었지만, 실전에서는 앞말을 덮는 형태로 나왔다.
>
> 보정: **이동할 문장이 미리 준비돼 있을 때만 이동한다. 준비돼 있지 않으면 그냥 멈춘다.** 침묵은 면접관이 다음 질문으로 채운다. 그건 사고가 아니다. 앞말을 뒤집는 게 사고다.

## 실제 기록

```text
17:14  "제가 지금 정확하게 기억은 나지 않아가지고"
17:53  "차트·대시보드는 마케터·기획자분들이 진행해 주셨고, 저는 베리언트를 나누고 기능을 구현하는 과정에 참여했습니다"
18:24  "…그 과정에 있어서 적극적으로 ab 테스트에 참여한 것 같습니다"
```

17:53까지는 정직하고 좋았다. v1이 준비시킨 대로 나온 답이다.
**18:24가 그걸 지웠다.** 30초 전에 "설계·해석은 안 했다"고 말해놓고 "적극적으로 참여했다"로 덮으면, 면접관은 앞 답까지 신뢰할 수 없게 된다.

A/B에 **7분 30초**를 쓰고 그 구간의 결론이 "설계와 해석은 제가 안 했습니다"였다. 시간을 가장 많이 쓴 구간에서 가장 적게 얻었다.

## 꼬리

### 역할을 작게 말하면 손해 아닌가요?

키워드: 검증 가능성, 꼬리질문, 신뢰

아니다. 크게 말하면 꼬리질문에서 검증당하고, 거기서 무너지면 나머지 답변의 신뢰까지 같이 떨어진다. 정확히 그은 경계는 그 자체로 신호다.

### 그럼 뭘 어필하나요?

키워드: 구현 깊이, 실패 케이스, 지금이라면

역할의 크기가 아니라 **깊이**로 어필한다. 내가 맡은 구현에서 뭘 실패로 봤는지(깜빡임), 지금이라면 뭘 다르게 하겠는지가 어필 지점이다.

# 지도 매물 렌더링 — 안 판 카드

## 키워드

```text
44초로 끝냄
최대 손실
클러스터링 요청취소 이전마커유지
```

## 답변

07:51에 이렇게 말하고 08:35에 다음 주제로 넘어갔다.

> 매물이 많은 지역일수록 매물을 빠르게 보여줘야 되는데 그런 부분을 제가 좀 고도화해서 화면에 그릴 때 깜빡거리지 않고 좀 더 자연스럽게 보이고 그런 노출 과정을 고민 많이 했습니다.

**한 문장, 44초.** 이번 면접의 최대 손실이다.

지도 위 대량 마커 렌더링은 프론트엔드 면접에서 혼자 15분 갈 수 있는 주제다. 대신 그 시간이 사주로 갔다. **가장 팔기 좋은 카드에 44초, 가장 설명하기 어려운 카드에 4분을 썼다.**

## 다시 쓰는 답변

**결론(0–10초)**

> 지도에서 매물이 몰린 지역일수록 렌더링이 느려지고 화면이 깜빡이는 문제가 있었고, 그걸 없애는 작업을 맡았습니다.

**구현(10–45초)** — 아래에서 실제로 한 것만 두세 개.

**결과(45–60초)** — 마커 수와 개선 폭. 수치가 없으면 "체감상 지도를 이동할 때 빈 화면이 보이던 게 없어지는 수준"까지만.

## 꼬리

### 매물이 몇 개까지 늘어나면 깨지나요?

키워드: 마커 수, 측정 시점

숫자 없이는 답이 안 되는 질문이다. 밀집 지역 최대 마커 수를 먼저 확인해둔다.

### 지도 라이브러리는 뭘 쓰셨나요?

키워드: 라이브러리 제약, 커스텀 여지

라이브러리가 제공하는 클러스터링을 썼는지, 직접 구현했는지가 갈린다. 이 답에 따라 이후 질문의 깊이가 달라진다.

# 사주 추천 — 4분을 4문장으로

## 키워드

```text
입력 제약 랭킹 가치
hard constraint는 예산과 지역
사주는 ranking signal
```

## 답변

도메인 설명을 줄이고 **구조**를 보여준다. 사주 → 용신 → 나무 → 동쪽 → 남동향 순서로 가면 면접관은 따라오지 못한다.

> 사주 정보만으로 추천하면 현실성이 없어서, 예산과 희망 지역을 반드시 지켜야 하는 조건으로 두고 사주에서 뽑은 방향 같은 요소는 순위를 매기는 데만 썼습니다. 실제로 선택 가능한 매물 안에서 탐색 동기를 하나 더 주는 방식입니다.

**여기서 멈춘다.** 용신·오행·남동향은 물어보면 설명한다.

## 실제 기록

08:35부터 12:35까지 **4분**, 되물음 **6회**. 같은 내용을 09:22 · 10:44 · 11:35 · 12:35에 네 번 반복했다.

그리고 이 4분 동안 이 기능의 **성과를 한 번도 말하지 않았다.** 면접관 입장에서는 "실험적 기능 하나 만들어봤다"로 끝난다.

## 확인 필요

> ✍️ **미확인(2026-08-31)** — "AI를 통해서 검증하고 추천했습니다"를 09:22 · 10:44 · 11:35 세 번 말했는데 **AI가 뭔지 한 번도 설명하지 않았다.** LLM인지, 룰 기반 스코어링인지, 임베딩인지 확인해서 한 문장으로 준비한다. 프론트엔드 면접이라도 "AI로 했습니다"만 반복하면 얼버무리는 걸로 들린다.

## 꼬리

### 이 기능 성과는 어땠나요?

키워드: 사용률, 없으면 정직하게

수치가 있으면 말하고, 없으면 "실험적으로 붙인 기능이라 지표를 따로 보진 않았습니다"로 **정직하게 끝낸다.** 지어내지 않는다.

### 사주라는 게 추천 근거로 타당한가요?

키워드: 재미 요소, 제약 안에서, 탐색 동기

타당성을 주장하지 않는다. **탐색 동기**로 설계했다고 말한다. 예산과 지역이라는 현실 조건을 먼저 만족시킨 뒤 순위에만 반영했기 때문에, 사용자가 손해 보는 선택으로 유도되지 않는 구조다.

# 숫자 없는 성과는 성과가 아니다

## 키워드

```text
35분에 숫자 1개
그것도 가상 예시
범위로라도 말한다
```

## 답변

한 답변에 숫자 하나를 넣는다. 성능 개선도 결과가 있어야 개선이다.

수치가 확실하지 않으면 범위로 말한다.

> 정확한 수치는 기억나지 않지만 체감상 ○○ 수준이었습니다.

**모른다고 말하는 건 감점이 아니고, 없는 숫자를 지어내는 게 감점이다.**

## 실제 기록

35분 전체에서 나온 숫자는 **"7억" 하나**였고, 그것도 사주 설명에 쓴 가상의 금액이다.

지도 렌더링 개선 · 사주 추천 기능 · A/B 테스트 · 단지 기능 — 전부 결과 수치가 없었다.

이건 말하기의 문제가 아니라 **자기 일을 평가 가능한 형태로 정리해본 적이 없다는 신호**에 가깝다. 말하기 연습보다 이게 먼저다.

## 찾을 것

```text
지도 — 밀집 지역 최대 마커 수, 개선 전후, 작업 시점
A/B — 실험 횟수, 한 실험의 기간, 결과가 남은 실험 하나
단지 — 전체 단지 수, 공통 기능 수, 확장된 사례 수
```

찾는 순서: `git log`와 PR 설명 → Amplitude 대시보드 → 스프린트 회고 → 기획 문서.

## 꼬리

### 개인 프로젝트도 숫자가 필요한가요?

키워드: 규모, 자동화 일수, 파일 수

규모는 숫자다. 모노레포 앱 수, 자동화가 며칠째 돌고 있는지, 마이그레이션한 import 건수 같은 게 다 숫자로 쓰인다.

# 마무리 — 역질문과 마지막 인상

## 키워드

```text
역질문 2~3개
답 듣고 한 문장 덧붙이기
응 금지
```

## 답변

역질문은 **2~3개** 준비한다. 하나만 던지고 끝나면 마지막 5분이 비어버린다.

답을 들은 뒤 "네"로 받지 말고 한 문장을 붙인다.

> 아 그러면 ○○ 쪽이 비중이 크겠네요. 감사합니다.

## 실제 기록

32:19에 던진 역질문은 좋았다. JD를 읽고 온 게 드러났다.

문제는 그다음이다. 33:44 "네" / 34:03 "네" / 34:16 **"응"** / 34:38 "아 알겠습니다 네 네 이상입니다".

**"응"은 면접에서 나오면 안 된다.** 긴장이 풀린 마지막 구간이라 나왔겠지만, 마지막 인상이다.

## 준비할 역질문

```text
1. JD에 모든 직군이 하나 이상의 직무를 해결한다고 되어 있는데 실제로 어떻게 진행되는지
2. 팀의 코드 리뷰와 배포 방식 — 직접 채울 것
3. 입사 후 첫 3개월에 맡게 될 범위 — 직접 채울 것
```

## 꼬리

### 역질문이 떨어지면요?

키워드: 방금 들은 답에서 파생

방금 들은 답에서 하나를 판다. "말씀하신 ○○은 어떤 단위로 진행되나요?" 준비한 질문보다 이게 더 자연스럽다.

# 확인된 강점 — 유지할 것

## 키워드

```text
B2B 확장 구조
harness lint 강제
역할 과장 안 함
사용자 관점
```

## 답변

고칠 것만 보면 왜곡된다. 이번 면접에서 **실제로 좋았던 것**도 기록해둔다.

- **20:43 · 21:21 B2B 확장 구조** — 공통 기능 개발 → 단지에 허용 → 검증되면 확장. 군더더기 없고 제품 사고가 드러난다. 이번 면접 최고 답변이다
- **25:39 harness → lint** — "CLAUDE.md에 적어둬도 누락되는 경우가 많더라고요. 그래서 강제했습니다." 실제로 겪어야 나오는 문장이다
- **17:53 역할 경계** — 덮기 전까지는 좋았다
- **07:04 "저 같은 경우에도 집을 구할 때"** — 사용자 관점으로 들어간 유일한 지점
- **32:19 역질문** — JD를 읽고 온 게 드러났다


## 꼬리

### 말을 못하는 게 문제인가요?

키워드: 문장 멀쩡함, 준비 상태, 습관

아니다. 전사본에 문장이 끊기거나 논리가 무너진 대목은 없다. 발음이 헷갈린 두 번을 빼면 35분 내내 문장이 멀쩡하다.
