Claude Code나 Codex 같은 CLI 에이전트는 띄워 둔 컴퓨터에서만 돈다. 노트북 뚜껑을 닫으면 에이전트도 멈추고 밖에서 진행 상황을 보려면 그 노트북을 다시 열어야 한다.

그래서 집에 있는 맥북을 에이전트 전용 서버로 돌리기로 했다. 에이전트는 집 맥북에서 돌고 밖에서는 휴대폰으로 화면만 띄운다. 여기에 쓴 도구가 [Orca](https://www.onorca.dev/)와 [Tailscale](https://tailscale.com/)이다.

## 1. 구성: 집 맥북이 서버, 휴대폰은 화면

[Orca](https://github.com/stablyai/orca)는 여러 코딩 에이전트를 나란히 돌리는 데스크톱 앱이다. 에이전트마다 git worktree를 따로 잡아 주고 Claude Code·Codex·OpenCode 같은 CLI를 그대로 감싼다. 에이전트는 각자 쓰던 구독 계정으로 돈다.

Orca에는 **Remote Orca Servers** 기능이 있다. 한 컴퓨터가 서버가 되어 프로젝트, worktree, 터미널, 에이전트 프로세스를 모두 갖고 있고 다른 기기는 그 서버에 접속하는 클라이언트가 된다. 공식 문서에 적힌 서버 쪽 특징은 이렇다.

- 클라이언트 연결이 끊겨도 에이전트는 서버에서 계속 돈다.
- 다시 연결하면 서버에 남아 있던 워크스페이스, 탭, 화면 배치로 돌아온다.
- 휴대폰용 Orca Mobile도 같은 서버에 접속해 같은 세션을 이어 본다.

남은 문제는 집 밖에서 집 맥북에 닿는 길이다. 공유기 포트를 열어 인터넷에 내놓는 방법도 있지만 Orca 문서는 **Orca 포트를 인터넷에 바로 열지 말라**고 적어 두었다. 대신 권하는 방법이 Tailscale이다. Tailscale은 내 기기들끼리만 보이는 사설망(tailnet)을 만들어 주고 각 기기에 `100.`으로 시작하는 주소를 붙여 준다. 포트를 열지 않아도 같은 tailnet에 로그인한 기기끼리는 이 주소로 서로 닿는다.

정리하면 구성은 이렇다.

| 기기 | 역할 | 설치한 것 |
| --- | --- | --- |
| 집 맥북 | 서버. 저장소, CLI 에이전트, 인증 정보가 여기 있다 | Orca, Tailscale, Claude Code·Codex |
| 휴대폰 | 클라이언트. 화면만 띄운다 | Orca Mobile, Tailscale |

![집 맥북에서 에이전트가 일하고, 닫힌 통로로 연결된 휴대폰에는 같은 화면이 뜬다](./structure.jpg)

### 다른 방법과 비교

휴대폰에서 집 컴퓨터의 Claude Code를 쓰는 방법은 Orca 말고도 있다.

| 방법 | 휴대폰에서 보이는 것 | 다루는 에이전트 |
| --- | --- | --- |
| Tailscale + SSH + tmux + 모바일 SSH 앱(Termius 등) | 터미널 | 터미널에서 띄운 것 전부 |
| Claude Code 공식 원격 기능 | Claude 앱 화면 | Claude Code |
| Orca + Tailscale | Orca Mobile 화면 | Claude Code·Codex·OpenCode 등, worktree별로 |

SSH와 tmux 조합은 따로 앱이 필요 없고 자료도 가장 많다. 다만 휴대폰 화면에서 터미널을 다뤄야 하고, 에이전트를 여러 개 돌리면 tmux 창을 오가며 찾아야 한다. Orca는 에이전트마다 worktree와 탭이 나뉘어 있어서 휴대폰에서도 어떤 에이전트가 무엇을 하는지 한눈에 보인다. Claude Code와 Codex를 같이 쓰기 때문에 Orca를 골랐다.

## 2. Tailscale로 두 기기를 한 망에 묶기

집 맥북과 휴대폰에 Tailscale을 깔고 **같은 계정으로 로그인**했다. 두 기기가 같은 tailnet에 들어가는 게 전부다.

로그인하고 나면 Tailscale 메뉴나 관리 콘솔에서 집 맥북의 주소를 확인할 수 있다. `100.x.y.z` 꼴이다. 이 주소는 다음 단계에서 Orca가 알아서 찾아 준다.

## 3. 집 맥북에서 접속 링크 만들기

집 맥북의 Orca에서 서버를 켜는 과정은 버튼 몇 번이면 끝난다.

1. Orca 데스크톱 앱에서 **Settings → Remote Orca Servers**를 연다.
2. **Advertise this app as a server** 아래의 **New Link**를 누른다.
3. **Connection address**에서 Tailscale 주소(`100.`으로 시작)를 고른다.
4. **Generate Access Link**를 누른다.

Tailscale 주소가 목록에 안 보이면 Tailscale이 연결돼 있는지 확인하고 **Connection address** 옆 새로고침 버튼을 누르면 된다. `127.0.0.1`은 서버 자신만 쓸 수 있는 주소라서 다른 기기용으로 고르면 안 된다.

이 링크는 비밀번호처럼 다뤄야 한다. 링크만 있으면 이 Orca 런타임에 접근할 수 있다. 메신저 대화방에 붙여 넣지 않고 휴대폰으로 바로 옮겼다.

## 4. 휴대폰에서 접속하기

휴대폰에서 Tailscale을 켜 두고 Orca Mobile에서 **Pair**를 눌러 집 맥북이 만든 QR 코드를 찍거나 링크를 붙여 넣었다.

연결되고 나면 휴대폰은 화면만 보여 준다. 코드, 터미널, 에이전트는 전부 집 맥북에 그대로 있다. 에이전트가 끝났는지, 승인을 기다리는지 밖에서 확인하고 다음 지시를 보낸다. 휴대폰 화면을 꺼도 집 맥북의 에이전트는 하던 일을 계속한다.

## 5. 맥북이 잠들지 않게

Orca 문서의 전제 조건 중 하나가 **서버 컴퓨터가 깨어 있고, tailnet에 연결돼 있고, Orca가 실행 중일 것**이다. 맥북은 기본 설정 그대로면 화면이 꺼질 때 잠든다. 잠든 맥북에는 원격으로 접속할 수 없다.

그래서 집 맥북은 이렇게 맞췄다.

- 전원 어댑터를 꽂아 둔다.
- **시스템 설정 → 배터리 → 옵션**에서 전원 어댑터에 연결됐을 때 디스플레이가 꺼져도 자동으로 잠자지 않도록 켠다.
- 뚜껑은 닫지 않고 열어 둔다. 외부 모니터 없이 뚜껑을 닫으면 맥북은 잠든다.

설정이 먹었는지는 터미널에서 확인한다.

```bash
pmset -g
```

## 6. 재부팅 뒤에도 다시 서버가 되도록

정전이나 업데이트로 맥북이 재부팅되면 Orca도 Tailscale도 꺼진다. 둘 다 **시스템 설정 → 일반 → 로그인 항목**에 넣어 로그인하면 자동으로 뜨게 했다.

여기서 걸리는 게 FileVault다. FileVault가 켜진 맥은 재부팅 뒤 비밀번호를 입력하기 전까지 사용자 세션이 열리지 않는다. Orca와 Tailscale은 사용자 세션에서 도는 앱이라서 집에 아무도 없을 때 재부팅되면 다음에 비밀번호를 칠 때까지 밖에서 접속할 수 없다. 이 부분은 풀지 않고 감수하기로 했다. 디스크 암호화를 끄는 것보다는 가끔 원격 접속이 끊기는 편이 낫다.

## 7. 링크 관리

Orca는 클라이언트마다 따로 토큰을 만들고 서버의 **Shared Server Access**에 목록으로 보여 준다.

- 휴지통 버튼으로 기기 하나의 접근만 끊을 수 있다. 연결된 클라이언트는 바로 끊긴다.
- 새 링크를 만들면 아직 쓰지 않은 이전 링크는 무효가 된다. 이미 연결된 기기는 그대로다.
- 링크를 엉뚱한 곳에 보냈다면 그 접근을 지우고 새 링크를 만들면 된다.

휴대폰을 바꾸거나 잃어버렸을 때 여기서 그 기기의 접근만 지우면 된다.

## 8. 이 구성으로 하는 일

세팅 자체보다 이걸로 무엇을 하느냐가 중요하다. 집 맥북을 서버로 둔 이유는 세 가지다.

### 밖에서 버그 고치기

배포해 둔 사이드 프로젝트에서 버그를 발견하는 건 대개 노트북이 없을 때다. 지금은 휴대폰으로 집 맥북의 Orca에 접속해 새 worktree를 열고 에이전트에게 수정을 맡긴다. 테스트가 통과하는지 보고 PR까지 올리게 한 뒤, 리뷰와 머지는 집에 와서 한다.

### 자기 전에 맡기고 아침에 고르기

Orca는 에이전트마다 worktree를 따로 잡아 준다. 그래서 같은 문제를 서로 다른 방식으로 동시에 풀게 할 수 있다. 자기 전에 접근법이 다른 지시 세 개를 걸어 두고 아침에 결과를 비교해 하나만 남긴다. 나머지 worktree는 지운다.

### 오래 걸리는 작업 걸어 두고 나가기

전체 빌드, E2E 테스트, 여러 파일에 걸친 리팩터링처럼 오래 걸리는 일은 집 맥북에 걸어 두고 나간다. 끝났는지, 어디서 막혔는지는 휴대폰으로 확인한다.

## 9. 집 맥북이 알아서 하는 일

8장은 내가 휴대폰으로 지시하는 일이다. 집 맥북이 늘 켜져 있으니 지시하지 않아도 정해진 시간에 도는 일도 맡길 수 있다.

예약 실행은 macOS의 launchd로 한다. 정해진 시각에 스크립트를 띄우고 스크립트 안에서 `claude -p`로 에이전트를 비대화형으로 돌린다. Orca는 그 결과를 휴대폰에서 확인하고 이어서 손볼 때 쓴다.

새벽 5시에 사이트 점검 스크립트를 띄우는 설정은 `~/Library/LaunchAgents/dev.danwoo.site-check.plist`에 이렇게 둔다.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>dev.danwoo.site-check</string>
  <key>ProgramArguments</key>
  <array>
    <string>/bin/zsh</string>
    <string>-lc</string>
    <string>~/automation/site-check.sh</string>
  </array>
  <key>StartCalendarInterval</key>
  <dict>
    <key>Hour</key>
    <integer>5</integer>
    <key>Minute</key>
    <integer>0</integer>
  </dict>
</dict>
</plist>
```

```bash
launchctl load ~/Library/LaunchAgents/dev.danwoo.site-check.plist
```

자동화에는 원칙을 하나 정했다. **에이전트는 PR까지만 올리고 머지는 내가 한다.** 사람 없이 도는 에이전트에게 머지 권한을 주지 않고 토큰 권한도 해당 저장소로 좁혔다.

### 이슈를 쓰면 아침에 PR

밖에서 떠오른 일은 휴대폰으로 GitHub 이슈에 적고 라벨을 붙인다. 집 맥북이 밤에 그 라벨이 붙은 이슈를 가져와 이슈마다 worktree를 만들고 에이전트에게 맡긴다. 아침에는 이슈마다 PR이 올라와 있고 나는 리뷰만 한다.

### 매일 새벽 사이트 점검

이 블로그와 프로젝트 허브를 매일 새벽 점검한다. 빌드가 되는지, 깨진 링크가 없는지, Lighthouse 점수가 떨어지지 않았는지 본다. 이상이 있으면 에이전트가 원인을 찾아 수정 PR 초안을 만든다.

예전에 `trailingSlash` 설정 때문에 슬래시 없는 내부 링크가 404가 나서 링크 63개를 한꺼번에 고친 적이 있다. 이런 문제를 누가 들어와 보기 전에 잡으려는 용도다.

### 나만 보는 정보 수집

관심 있는 라이브러리의 릴리스 노트, GitHub 트렌딩, 기술 뉴스를 매일 모아 요약한다. 요약은 저장소 밖의 노트에 쌓고 공개하지 않는다. 블로그 글감이 필요할 때 여기서 꺼내 쓴다. 예전에 이 블로그에 AI 뉴스를 자동으로 올리다가 [껐는데](/posts/too-easy-to-build/), 모으는 것까지만 자동으로 두고 무엇을 쓸지는 직접 고른다.

### 의존성 업데이트와 마이그레이션

매주 `pnpm outdated`로 메이저 업데이트를 확인한다. 올릴 게 있으면 worktree에서 올려 보고 깨지는 코드는 에이전트가 고친다. 테스트까지 통과한 것만 PR로 올라온다. 버전만 올려 주는 업데이트 봇과 달리 깨진 코드를 고치는 데까지 간다.

자동화도 Claude 구독 한도를 같이 쓴다. 밤새 많이 돌리면 다음 날 쓸 몫이 줄어서 작업마다 도는 횟수와 시각을 나눠 두었다.

## 정리

- 집 맥북: Orca를 서버로 켜고 Tailscale 주소로 접속 링크를 만든다.
- 휴대폰: 같은 tailnet에 로그인하고 Orca Mobile로 페어링한다.
- 맥북은 전원 연결, 잠자기 해제, 로그인 항목 등록까지 해 둔다.
- 포트포워딩은 하지 않는다. 링크는 비밀번호처럼 다룬다.
- 휴대폰으로는 밖에서 버그 수정, 밤사이 병렬 실험, 오래 걸리는 작업을 맡긴다.
- launchd 예약으로는 이슈 처리, 사이트 점검, 정보 수집, 의존성 업데이트를 돌린다. 머지는 항상 직접 한다.

에이전트에게 일을 얼마나 맡길지는 [AI에게 코드를 맡기기 위한 위임의 조건](/posts/delegating-code-to-ai/)에 정리해 두었다.
