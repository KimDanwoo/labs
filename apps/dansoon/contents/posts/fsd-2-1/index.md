## 들어가며

Feature-Sliced Design(FSD)은 기능 단위로 코드를 나누는 구조적 설계 방식입니다.

2.1 버전에서 가장 크게 달라진 점은 **화면을 분해하는 기준이 ‘Feature 중심’에서 ‘Page 우선(Page-first)’으로 바뀌었다는 점**입니다.

이는 기존 구조를 뒤집었다기보다,

현실적인 개발 흐름을 더 잘 반영한 방향으로 **멘탈 모델을 재정의한 변화**라고 볼 수 있습니다.

## 1\. FSD 2.0 — Feature 중심 구조

FSD 2.0에서는 **Feature가 가장 중요한 단위**였습니다.

```text
Page
 └─ Feature
      └─ Entity
```

특징:

-   Feature가 기능·데이터·UI를 모두 포함하는 중심 레이어
-   Page는 Feature를 조합하는 얇은 계층
-   Feature 단위 재사용성과 도메인 중심 구조화에 초점

단점은 시간이 지날수록 Feature가 비대해지고,

Page의 역할이 점점 모호해진다는 점입니다.

## 2\. 왜 FSD 2.1이 필요했나?

실제 서비스는 “기능”보다 “페이지 흐름(Flow)”이 중심입니다.

예를 들어:

-   리스트 페이지에서 필터 → 정렬
-   상세 페이지에서 여러 데이터 조합
-   페이지 단위 전처리/분기
-   특정 페이지에서만 필요한 UI·조건

이러한 흐름은 Feature 내부에 담기 어렵고,

결국 Page가 자연스럽게 더 많은 책임을 갖게 됩니다.

즉,

> 현실적인 개발 방식이 이미 Page 중심이었고,
> 
> FSD 2.1은 이를 구조적으로 명확히 정리한 버전이다.

## 3\. FSD 2.1 — Page-First 구조

FSD 2.1의 핵심은 명확합니다.

Page에서 흐름을 정의하고,

그 아래에 Widget과 Feature가 배치되는 형태로 분해 기준이 변경됐습니다.

### 레이어별 책임

-   **Page**
    -   화면 흐름(Flow) 정의
    -   필요한 데이터 준비
    -   어떤 Widget/Feature를 사용할지 결정하는 상위 조립 계층
-   **Widget**
    -   페이지를 구성하는 UI 조각을 묶는 단위
    -   2.0에도 존재했지만 2.1에서 역할이 더 명확해짐
-   **Feature**
    -   단일 기능 구현 (UI + 최소한의 로직)
    -   더 이상 페이지 조립 역할을 갖지 않음
-   **Entity**
    -   순수 도메인/데이터 모델

## 4\. 핵심 차이 요약

항목 FSD 2.0 FSD 2.1

| 분해 기준 | Feature 중심 | Page-first(페이지 먼저) |
| --- | --- | --- |
| Feature 역할 | 기능·데이터·UI 모두 담당, 비대해지기 쉬움 | 단일 기능·UI 단위로 축소 |
| Page 역할 | 얇은 조립 계층 | 흐름·데이터 준비를 맡는 핵심 계층 |
| Widget | 개념은 있었으나 비중이 작음 | Page와 Feature 사이의 UI 조합 레이어로 명확해짐 |
| 구조 의도 | 도메인 중심 분리 | 실제 화면 구성/흐름 중심 분리 |

## 5\. FSD 2.1의 장점

-   Page 단위 흐름이 선명해짐
-   Feature가 가벼워지고 재사용성이 증가
-   Page → Feature 흐름이 단순해짐
-   실제 화면 구성 방식과 디렉토리 구조가 자연스럽게 일치
-   협업 시 “이 로직이 어디에 있어야 하는가?” 기준이 명확해짐

결국,

> 실제 개발 과정을 구조가 그대로 반영하게 된다.

## 마무리

FSD 2.1의 변화는 갑작스러운 규칙 변경이 아니라,

**현실적인 화면 구성 방식이 Page 중심이라는 사실을 구조에 반영한 결과**입니다.

-   2.0은 기능 중심
-   2.1은 페이지 흐름 중심
