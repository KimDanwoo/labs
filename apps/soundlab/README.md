# Soundlab

DANWOO의 곡을 커버로 탐색하고 재생하는 음악 사이트. SoundCloud 위젯으로 재생하며 원본 음원은 배포하지 않는다.

## 음악 관리

- `pnpm --filter soundlab sync-tracks`: 공개 곡의 모든 페이지를 수집한다. 기존 곡이 사라지면 `isAvailable: false`로 보존해 기존 URL이 404가 되지 않게 한다. 전체 목록과 폰트를 받은 후에만 목록을 교체한다.
- `pnpm --filter soundlab sync-tracks --strict`: 외부 서비스 실패를 종료 코드로 알린다. 예약 동기화는 이 모드를 쓴다. 일반 빌드는 기존 아카이브로 계속 진행한다.
- `pnpm --filter soundlab analyze-audio "원본 폴더"`: 원본과 업로드된 곡의 길이를 대조해 주파수 대역과 비트 신호를 생성한다. 파일명으로 곡을 찾으며 제목이 중복되면 길이로 구분한다.
- `pnpm --filter soundlab build:highlights`: 분석 신호의 중역 에너지가 가장 높은 15초 구간을 계산해 감상 시작점을 생성한다.
- `pnpm --filter soundlab check:signals --strict`: 모든 공개 곡의 분석 신호가 존재하고 유효한지 검사한다. `--strict` 없이 실행하면 누락은 보고하고 손상된 신호만 실패로 처리한다.

`tracks.ts`, `highlights.ts`, `public/signals/*`는 생성물이다. 곡 설명은 SoundCloud에 등록된 원문을 일반 텍스트로 표시한다. SoundCloud 공개 웹 클라이언트의 목록 수집 경로가 바뀌면 예약 동기화가 실패할 수 있으며, 기존 아카이브는 유지된다.

## 큐레이션과 감상

첫 화면 `/`은 커버 아트로 탐색하는 아카이브다. 커버를 선택하면 `/t/<id>` 감상 화면에서 재생한다. 상단의 아카이브·감상 메뉴와 브라우저 뒤로 가기는 재생 엔진을 유지하면서 화면만 전환한다. 검색·즐겨찾기·최근 감상 필터는 아카이브와 재생목록이 공유한다. 플레이리스트와 감상 기록은 재생목록의 접힌 메뉴에서 확인한다.

`src/views/player/config/collections.ts`에서 세트의 제목·소개·곡 ID 순서를 편집한다. 자동 생성 곡 정보와 별개이므로 동기화해도 덮어쓰지 않는다. 검색과 필터는 화면에 보이는 곡만 바꾸고, `세트 재생` 또는 `이 목록 재생`을 눌렀을 때 실제 재생 순서가 바뀐다. 세트 밖의 곡을 선택하면 전체 곡 순서로 돌아간다.

즐겨찾기·최근 감상 30곡·누적 감상 시간·세트 감상 시간과 재생 통계는 이 브라우저의 `soundlab:library:v1`에 저장한다. 외부 분석 서버로 전송하지 않는다. 실제 재생 진행 이벤트를 집계하며 탐색으로 건너뛴 시간은 감상 시간에서 제외한다. 기록 지우기는 즐겨찾기를 유지한다. 계정·다른 기기 간 동기화는 없다.

곡 링크는 `/t/<id>`, 시작 위치는 `?t=<초>`다. 링크로 들어온 곡과 위치를 이어 듣기 기록보다 우선한다. 공유 메뉴에서 곡 처음·현재 위치·기기 공유를 선택할 수 있고, 클립보드 권한이 없으면 복사할 URL을 표시한다.

세트 재생은 SoundCloud 단일 곡 로딩으로 순서를 제어한다. 실제 모바일 OS가 탭을 중지했을 때 다음 곡으로 이어지는 동작은 기기별 확인이 필요하다. 전체 곡 재생은 가능한 경우 위젯의 네이티브 목록 전환을 사용한다.

## 검증

`pnpm --filter soundlab test`, `lint`, `typecheck`와 루트의 `pnpm check:architecture`를 실행한다. 재생 순서·재시도·검색 단축키·외부 입력 검증·아카이브 보존을 회귀 테스트한다. 브라우저에서는 첫 세트 재생, 종료 시 다음 곡, 즐겨찾기 복원, 감상 구간, 공유, 화면 효과 모드, 연결 복구를 확인한다.
