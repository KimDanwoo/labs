# 별도쿠 알고리즘 정리

> 퍼즐 생성·검증·난이도의 전체 그림. 코드: `src/entities/stardoku/model/{generator,solver}.ts`

## 0. 전제 (게임 규칙)

N×N 보드, 색 구역 N개. **각 행·열·구역에 별 정확히 1개, 별끼리 대각선 포함 인접 금지.**
모든 퍼즐은 ① 유일해 ② 찍기 없이(노게싱) 논리만으로 완주 가능해야 한다.

## 1. 생성 파이프라인

```
[1] 별 배치          순열 백트래킹. 행별 열 = 순열(행·열 1개씩),
                     인접 행 열 차 ≥ 2 (대각 인접 자동 배제)
[2] 구역 성장        별 칸 N개를 씨앗으로 랜덤 flood-fill
    ├─ 엔트리 정책   ≤6×6: 1칸 구역 금지 / ≥7×7: 1칸 구역 정확히 1개 동결
    ├─ 1페이즈       동결 제외 전 구역을 1회씩 확장 → 최소 2칸 구조 보장
    └─ 2페이즈       성장 확률 ∝ 크기³ (rich-get-richer)
                     → 큰 구역 소수 + 작은 구역 다수 편차
                     → 작은/한 줄 구역이 제약을 강화 → 유일해율 급상승
                     (균등 성장은 8×8+에서 유일해율 0%였음)
[3] 논리 솔버 검증   아래 기법만 반복 적용해 완주되면 채택
                     완주 = 강제 수순만으로 풀림 = 유일해 + 노게싱 보장
[4] 미충족 시 재시도 (수 ms/판, 상한 500회)
```

## 2. 솔버 기법 카탈로그 (사람이 쓰는 순서대로)

| 티어        | 기법                                                            | 사람 관점                                     |
| ----------- | --------------------------------------------------------------- | --------------------------------------------- |
| **T1 배치** | (a) 구역에 후보 1칸 → ⭐                                        | "이 색은 여기뿐이네"                          |
| **T1 배치** | (b) 행/열에 후보 1칸 → ⭐                                       | "이 줄은 여기뿐이네"                          |
| **T2 소거** | (c) 구역 후보가 한 행/열에 갇힘 → 그 줄의 타 구역 소거          | "이 색이 이 줄을 차지하니까 남들은 못 옴"     |
| **T2 소거** | (d) 행/열 후보가 전부 한 구역 → 그 구역을 그 줄로 고정          | "이 줄은 이 색 차지니까 색의 딴 줄 칸은 탈락" |
| **T3 가정** | (e) 한 수 앞 모순: 별을 뒀다 치면 어떤 줄/구역 후보 전멸 → 소거 | "여기 두면 저 줄이 막히네 → X"                |

- 별을 놓을 때마다 행·열·구역·8방향 이웃이 소거된다(전파). T1만으로 끝까지 풀리는 판 = **연쇄 자동 진행 = 시시함**.
- T2가 필요한 판 = 줄↔구역 관계를 읽어야 함 = **"생각 좀 해야" 풀림**.
- T3가 필요한 판 = 한 수 앞을 그려봐야 함 = **어려움** (9×9에서 자연 발생).

## 3. 난이도 레버 현황

| 레버           | 현재 값                         | 효과             |
| -------------- | ------------------------------- | ---------------- |
| 보드 크기      | 일반 5~8 랜덤, 5배수 스테이지 9 | 탐색 공간        |
| 1칸 구역       | ≤6 금지 / ≥7 정확히 1개         | 시작 엔트리 유무 |
| 최소 구역 크기 | 2 (동결 제외)                   | 공짜 별 방지     |
| 목숨/힌트      | 3 / 3                           | 실수·막힘 완충   |

**빠진 레버(이번 제안): 풀이 경로의 질.** 지금은 T1 연쇄로 끝나는 판도 통과된다 → 쉬운 판이 섞여 나온다.

## 4. 기법 티어 기반 난이도 등급 (구현 완료)

솔버(`solveByLogic`)가 완주하며 쓴 최고 티어를 `difficulty`로 반환한다:

```
EASY   = T1만으로 완주 (연쇄 자동 진행)   → 전부 폐기
MEDIUM = T2(c/d)가 1회 이상 필요
HARD   = T3(e)가 1회 이상 필요
```

크기별 **수락 밴드** (`generator.ts`의 `isAcceptableDifficulty`):

| 보드         | 수락 등급       | 의도                                 | 측정 분포\*                    |
| ------------ | --------------- | ------------------------------------ | ------------------------------ |
| 5×5~6×6      | **MEDIUM만**    | 자동 진행 금지, 작은 판에 T3는 과함  | easy 0% — 이미 구조적으로 없음 |
| 7×7~8×8      | **MEDIUM·HARD** | 공짜 별로 시작하되 중반은 추리 필수  | easy 4~7%가 걸러짐             |
| 9×9 (대형판) | **MEDIUM·HARD** | HARD 자연 발생 = 5배수 스테이지의 벽 | hard ~25% 포함                 |

\* 시드 프로브 300회/크기. 밴드 수락률: 5×5 27% · 6×6 16% · 7~9 15~21% → 평균 4~7회 시도(수 ms).

흥미로운 발견: 소형 판은 "1칸 금지 + 최소 2칸" 구조만으로 EASY가 0% — 쉬움의 원천은 **7+에서 공짜 별이 만드는 T1 연쇄**였고, 이 밴드가 그걸 정확히 걸러낸다.
