# PRD — 별도쿠 (Stardoku)

> awesome-sudoku 앱에 추가하는 세 번째 게임. Star Battle(LinkedIn Queens) 계열 논리 퍼즐로, Meowdoku의 규칙을 별(⭐) 테마로 구현한다.

- **상태**: Draft v1
- **작성일**: 2026-08-06
- **대상 앱**: `apps/awesome-sudoku` (모드 추가 확정)

---

## 1. 배경 / 목표

**배경.** awesome-sudoku는 클래식·킬러 스도쿠를 제공한다. 같은 "논리 소거 퍼즐" 계열이면서 규칙이 훨씬 단순하고 한 판이 짧은(1~5분) 게임을 추가해 가볍게 반복 플레이할 거리를 만든다.

**목표 (v1)**

1. 행·열·구역 제약 기반 별 배치 퍼즐을 플레이할 수 있다.
2. 모든 퍼즐은 **랜덤 생성 + 유일해 보장**이다 (고정 레벨 데이터 없음).
3. **스테이지 진행형**: 스테이지가 1부터 무한히 올라간다. 일반 스테이지는 보드 크기가 랜덤이고, 5의 배수 스테이지는 9×9 대형판. 진행도는 기기에 저장된다.
4. 기존 앱의 테마(라이트/다크)·비주얼 언어·FSD 구조를 그대로 따른다.

**비목표 (v1에서 제외)**

- 별 2개 변형(정통 Star Battle 2★), 데일리 퍼즐, 온라인 대전, 튜토리얼 애니메이션. → 전부 v2 후보.

## 2. 게임 규

N×N 보드가 색으로 구분된 **N개의 연결된 구역**으로 나뉜다.

1. **각 행에 별 정확히 1개**
2. **각 열에 별 정확히 1개**
3. **각 색 구역에 별 정확히 1개**
4. **별끼리 인접 금지** — 대각선 포함 8방향으로 서로 닿을 수 없다

네 조건을 모두 만족하면 스테이지 클리어.

### 조작 (제스처)

| 제스처 | 결과 |
| --- | --- |
| 빈칸 탭 1번 | ❌ (소거 메모) |
| 연속 탭 2번 (더블탭, ~400ms) | ⭐ 배치 시도 |
| ❌ 탭 1번 | ❌ 제거 |
| ⭐ 탭 1번 | ⭐ 제거 |
| **빈칸에서 드래그** | 지나간 빈칸에 ❌ 일괄 마킹 (드래그로 친 ❌는 더블탭 승격 대상 아님) |

- 마크(❌/⭐)가 생겨도 **셀·보드 크기는 절대 변하지 않는다** (`grid-template-rows` 고정, 레이아웃 시프트 금지).

### 목숨 시스템

- 목숨 **3개**로 시작한다.
- ⭐를 **정답 위치가 아닌 칸**에 두면: 별이 놓이지 않고(즉시 거부 + 에러 플래시) **목숨 −1**.
- 목숨 0 → **게임 오버**: **점수 −3** + **이전 스테이지로 후퇴**(스테이지 1이면 1 유지). 게임 오버 상태에서 어떤 버튼을 눌러도 후퇴로 수렴한다(감점·후퇴 회피 불가).
- 정답 검증이 즉시 이뤄지므로 보드에 남는 별은 항상 정답 → **별 N개를 모두 놓으면 클리어**.
- ❌ 마킹은 틀려도 페널티 없다 (메모일 뿐).

### 힌트 & 점수 (랭킹 기반)

- 판당 **힌트 3개** — 사용 시 정답 별 하나가 공개된다(무작위 미배치 위치).
- **클리어 점수 = 남은 힌트**: 힌트 없이 +3, 1개당 −1, 3개 다 쓰면 +0.
- 게임 오버 = −3점. 점수는 **누적**(음수 가능)이고 localStorage에 영속 — 랭킹의 기반 값.

### 랭킹 (Firebase 연동)

- Firestore **`stardokuScores` 컬렉션, 유저당 1문서(docId = uid)** — 로그인 상태에서 점수·스테이지가 바뀔 때마다 로컬 누적값을 upsert 미러링 (`useSyncStardokuScore`).
- `/leaderboard`에 **"별도쿠" 탭** — score 내림차순 상위 100명 (순위·플레이어·점수·스테이지).
- 0점·1스테이지(무기록) 유저는 문서를 만들지 않아 랭킹 오염 방지. 랭킹 쓰기 실패는 게임 진행을 막지 않는다.
- 멀티 디바이스는 last-write-wins(점수가 기기 로컬 기준) — 서버 권위 점수는 v2.
- **Firestore 보안 규칙 필요(콘솔)**: 읽기 공개, 쓰기는 `request.auth.uid == documentId`.

## 3. 스테이지 / 난이도 시스템

- 스테이지는 **1부터 무한 진행**. 클리어하면 다음 스테이지가 즉시 랜덤 생성된다.
- 갈수록 어려워지는 커브가 아니라 **랜덤 + 주기적 대형판** 구조:

| 스테이지 | 보드 |
| --- | --- |
| 일반 (5의 배수 아님) | **5×5 ~ 8×8 중 랜덤** |
| **5의 배수 (5, 10, 15, …)** | **9×9 고정 (대형판)** |

- 상수로 정의해 튜닝 가능하게 둔다: `RANDOM_SIZE_MIN = 5`, `RANDOM_SIZE_MAX = 8`, `BIG_STAGE_STEP = 5`, `BIG_BOARD_SIZE = 9`.
- 참고: 이 규칙(대각 인접 금지)에서 2×2·3×3은 해가 없고 4×4는 자명해서, 랜덤 하한은 5로 둔다.
- 스테이지 번호는 클리어 카운터 역할 — 크기 외 추가 난이도 변화(논리 깊이 측정 등)는 v2 후보.
- **저장**: 현재 스테이지 번호 + 진행 중인 판(퍼즐·마킹)을 localStorage에 저장 — 새로고침해도 이어서 플레이.

## 4. 퍼즐 생성 알고리즘 (핵심)

고정 레벨 없이 매판 생성하되, 유일해만으로는 부족하다 — **사람이 논리 기법 체인으로 노게싱 완주 가능 + 첫 수가 눈에 보이는 퍼즐**만 채택한다.

```
1. 별 배치 생성: 순열 백트래킹으로 유효한 별 N개 배치를 먼저 만든다
   (행·열 1개씩 = 순열, 인접 행의 열 차이 ≥ 2로 대각 인접 배제)
2. 구역 성장: 각 별 칸을 씨앗으로 랜덤 flood-fill, 2페이즈
   - 크기별 엔트리 정책 (플레이테스트로 튜닝): 6×6 이하 — 1칸 구역 금지(공짜 별 = 시시함)
     / 7×7 이상 — 1칸 구역 정확히 1개를 동결·보장(시작 엔트리 없으면 못 푼다)
   - 1페이즈: 동결 구역 외 모든 구역을 1회씩 확장 → 최소 2칸 구조 보장
   - 2페이즈: 성장 확률을 크기³에 비례(rich-get-richer) → "큰 구역 소수 +
     작은 구역 다수" 편차. 작은/한 줄 구역이 제약을 강화해 유일해율이 뛴다
3. 논리 솔버 검증: 사람이 쓰는 기법만 반복 적용해 완주되는지 확인
   - 배치: (a) 구역 후보 1개 → 별  (b) 행/열 후보 1개 → 별
   - 소거: (c) 구역 후보가 한 행/열에 갇힘 → 그 줄의 타 구역 칸 소거
           (d) 행/열 후보가 전부 한 구역 → 그 구역을 그 줄로 고정
           (e) 한 수 앞 모순: 별을 두면 어떤 줄/구역 후보가 전멸 → 그 칸 소거
   완주 = 강제 수순만으로 풀림 = 유일해 자동 보장 + 노게싱 보장
   (첫 수도 이 기법들로 유도된다 — 공짜 엔트리 없이 솔버 완주가 시작점을 보장)
4. 난이도 밴드 필터: 솔버가 쓴 최고 기법 티어로 판을 등급화(easy/medium/hard)
   - easy(T1 배치 연쇄만으로 풀림) → 전부 폐기 ("너무 쉬움" 방지)
   - 소형(≤6): medium만 / 대형(≥7): medium·hard 허용
5. 미충족 시 1부터 재시도 (밴드 수락률 15~27% → 평균 4~7회, 수 ms)
```

> 상세는 `docs/stardoku-algorithm.md` 참고.

- 솔버·생성기는 **순수 함수**로 작성하고 vitest 단위 테스트를 붙인다(제약 충족·구역 연결성·논리 완주·브루트포스 해 카운트 이중 검증).
- **프로토타입 검증 완료**: 위 파이프라인을 스크립트로 구현해 6×6 기준 수십 회 시도 내(수 ms)에 조건 충족 퍼즐이 나옴 — 클라이언트 동기 생성으로 충분(웹워커 불필요). 목업의 퍼즐도 이 생성기 산출물.
- 난이도: 일반 스테이지는 기본 기법 (a)~(c)만으로 풀리는 판. 9×9 대형판은 기법 체인이 자연히 길어진다. 고급 기법 요구 판(2×2 배제 등)은 v2 후보.

## 5. UX / 화면

**진입**: 홈 헤더의 모드 선택 영역에 `별도쿠` 진입 버튼 추가 → **`/stardoku` 라우트로 이동** (기존 클래식/킬러는 atom 전환이지만, 별도쿠는 별개 화면이므로 URL 라우팅 — 프로젝트 규칙 "화면 전환은 URL 기반"과 일치).

**게임 화면 구성** (HomePage 레이아웃 관례 재사용):

- 헤더: 홈으로 돌아가기 · 스테이지 번호 + 보드 크기(`STAGE 12 · 6×6`) · ThemeToggle
- 상태 라인: ⭐ 진행 카운터(`n / N`) · 누적 점수 · 남은 목숨(❤️❤️❤️)
- 보드: 색 구역이 배경색으로 칠해진 N×N 그리드. 구역 경계는 굵은 보더. 탭/더블탭/드래그 제스처
- 틀린 별: 해당 셀 에러 플래시(빨간 링, ~0.6s) + 목숨 하트 차감
- 하단 컨트롤: 💡 힌트(남은 개수 표시, 0이면 비활성) · 다시 시작(현재 판 리셋) · 새 퍼즐(같은 스테이지 재생성)
- 결과 바텀시트(GameResultSheet 패턴) 성공/실패 분기: 클리어 → 획득 점수 `+N` + "다음 스테이지" / 게임 오버 → `−3점` + "이전 스테이지로"

**모바일 우선** (360px 최소), 데스크톱은 기존 2컬럼 관례 따름.

**구역 색상 (색약 대응)**: 라이트/다크 9색 팔레트를 색각이상 시뮬레이션으로 검증해 선정 — hue만이 아니라 **음영(100↔400) 명도 차이 + 중성 회색**을 제2 식별축으로 사용. 정상·적록(protan/deutan)·청황(tritan) 전 모드에서 쌍별 Lab ΔE ≥ 12.5(tritan 8.8) 보장. 구역 경계는 굵은 보더(불투명도 85%)로 색과 무관한 단서를 중복 제공. 재검증: `node scripts/cvd-palette.mjs` (Machado 2009 행렬 + 배경 블렌딩 기반 max-min 탐색).

## 6. 기술 설계

기존 `GAME_MODE`(classic/killer)와 `SudokuState`에 **끼워 넣지 않는다** — 스도쿠 전용 상태(numberCounts, notes, solution 등)와 도메인이 달라 오염됨. 별개 FSD 슬라이스 + 별개 라우트로 간다.

```
apps/awesome-sudoku/
  app/stardoku/page.tsx                  # 얇은 라우트 → StardokuPage
  src/
    entities/stardoku/
      model/types.ts                     # StardokuPuzzle, CellMark, …
      model/constants.ts                 # CELL_MARK, STAGE_SIZE_STEP, MAX_BOARD_SIZE, 구역 팔레트
      model/generator.ts                 # 별 배치 + 구역 성장 + 유일해 검증 (순수)
      model/solver.ts                    # 해 카운터, 위반 검출 (순수)
      model/__tests__/                   # vitest
    features/stardoku-game/
      model/atoms/                       # stage·puzzle·marks·lives·hints·score(영속) + 파생 클리어/게임오버 atom
      ui/                                # StardokuCell, StageBadge, StardokuResultSheet, 컨트롤 버튼
    widgets/stardoku-board/ui/           # 보드 위젯 (구역 색·경계 렌더)
    views/stardoku/ui/StardokuPage.tsx   # 화면 조립
```

- **상태**: Jotai `atomWithStorage`(키 prefix `stardoku:`) — 기존 `primitives.ts` 관례 동일.
- **재사용**: theme(라이트/다크), `cn` 유틸, GameResultSheet의 바텀시트 패턴, 레이아웃 관례.
- **FSD 의존 방향**: views → widgets → features → entities. 기존 슬라이스(sudoku-game 등)와 cross-import 없음.

## 7. 검증 / 완료 기준

- [ ] 생성기 단위 테스트: 5~9 각 크기에서 (a) 제약 충족 (b) 구역 연결성 (c) 유일해 — 크기별 반복 생성 통과
- [ ] 목숨 테스트: 오답 별 → 거부 + lives −1 / lives 0 → 게임오버 / ❌는 페널티 없음
- [ ] 클리어 판정 테스트: 정답 별 N개 배치 시 클리어
- [ ] 제스처 테스트: 탭 → ❌, 더블탭 → ⭐ 시도, ❌ 탭 → 제거, 드래그 → ❌ 일괄
- [ ] 마크 표시/제거 시 셀·보드 크기 불변 (레이아웃 시프트 없음)
- [ ] 새로고침 후 스테이지·진행 판·목숨 복원
- [ ] `pnpm --filter awesome-sudoku lint` + `tsc --noEmit` 통과
- [ ] 라이트/다크에서 구역 색 구분 및 위반 하이라이트 시인성 확인 (수동)

## 8. 결정 사항 (확정)

1. **홈 진입 UI** → 모드 셀렉터 세 번째 탭(클래식 | 킬러 | 별도쿠), 누르면 `/stardoku` 라우팅.
2. **테마** → 별(⭐) 확정. 아이콘은 `STAR_ICON` 상수 하나로 분리(교체 용이).
3. **대형판 주기** → 5의 배수 스테이지 = 9×9. 추가 특수화(시간 제한 등)는 v2 검토.
